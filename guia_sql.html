01

Introducción y conceptos fundamentales

-- de qué hablamos cuando hablamos de SQL

1.1 · ¿Qué es SQL?

SQL (Structured Query Language) es el lenguaje estándar para trabajar con bases de datos relacionales. No es un lenguaje de programación general: es un lenguaje declarativo — le dices qué quieres, no cómo conseguirlo. Se divide en tres grandes familias de sentencias:

DDL

Data Definition Language. Define la estructura: CREATE, ALTER, DROP.

DML

Data Manipulation Language. Manipula los datos: SELECT, INSERT, UPDATE, DELETE.

DCL

Data Control Language. Gestiona permisos: GRANT, REVOKE.

1.2 · Modelo relacional básico

  • Tabla = entidad (ej. clientes)
  • Fila = registro o tupla (ej. un cliente concreto)
  • Columna = atributo (ej. nombre)
  • Clave primaria (PK) = identifica cada fila de forma única
  • Clave foránea (FK) = relaciona una tabla con otra

1.3 · Relaciones entre tablas

TipoDescripciónEjemplo
1:NUn registro de A se relaciona con muchos de BUn cliente → muchos pedidos
N:1Muchos de A se relacionan con uno de BMuchos pedidos → un cliente
N:NMuchos de A con muchos de BProductos ↔ Proveedores (tabla intermedia)

2.3 · Claves primarias compuestas

Cuando una tabla existe solo para resolver una relación N:N — como productos_proveedores — su clave primaria suele ser la combinación de las dos claves foráneas:

sql
-- Tabla intermedia para N:N (productos y proveedores)
CREATE TABLE productos_proveedores (
    id_producto INT,
    id_proveedor INT,
    fecha_asignacion DATE DEFAULT CURRENT_DATE,
    PRIMARY KEY (id_producto, id_proveedor),  -- PK compuesta
    FOREIGN KEY (id_producto) REFERENCES productos(id_producto),
    FOREIGN KEY (id_proveedor) REFERENCES proveedores(id_proveedor)
);
03

DDL — Definición de estructuras

-- construir el esqueleto de la base de datos

3.1 · CREATE TABLE

sql
CREATE TABLE clientes (
    id_cliente INT PRIMARY KEY AUTO_INCREMENT,
    nombre VARCHAR(100) NOT NULL,
    email VARCHAR(100) UNIQUE NOT NULL,
    telefono VARCHAR(15),
    ciudad VARCHAR(50) DEFAULT 'Madrid',
    fecha_alta DATE DEFAULT CURRENT_DATE,
    activo BOOLEAN DEFAULT TRUE,
    CHECK (LENGTH(telefono) >= 9 OR telefono IS NULL)  -- CHECK constraint
);

CREATE TABLE categorias (
    id_categoria INT PRIMARY KEY AUTO_INCREMENT,
    nombre VARCHAR(50) NOT NULL UNIQUE,
    descripcion TEXT
);

CREATE TABLE productos (
    id_producto INT PRIMARY KEY AUTO_INCREMENT,
    nombre VARCHAR(100) NOT NULL,
    precio DECIMAL(10,2) NOT NULL CHECK (precio > 0),
    stock INT NOT NULL DEFAULT 0 CHECK (stock >= 0),
    id_categoria INT,
    FOREIGN KEY (id_categoria) REFERENCES categorias(id_categoria)
);

CREATE TABLE pedidos (
    id_pedido INT PRIMARY KEY AUTO_INCREMENT,
    id_cliente INT NOT NULL,
    fecha_pedido DATETIME DEFAULT CURRENT_TIMESTAMP,
    total DECIMAL(10,2) DEFAULT 0,
    FOREIGN KEY (id_cliente) REFERENCES clientes(id_cliente) ON DELETE CASCADE
);
-- ON DELETE CASCADE: si se borra el cliente, se borran sus pedidos

3.2 · ALTER TABLE

sql
-- Añadir columna
ALTER TABLE productos ADD descripcion TEXT;

-- Modificar tipo de columna
ALTER TABLE productos MODIFY precio DECIMAL(12,2);

-- Añadir restricción
ALTER TABLE productos ADD CHECK (stock >= 0);

-- Eliminar columna
ALTER TABLE productos DROP COLUMN descripcion;

-- Renombrar tabla
ALTER TABLE clientes RENAME TO usuarios;

3.3 · DROP TABLE

sql
DROP TABLE productos_proveedores;  -- primero las que tienen FK
DROP TABLE proveedores;

3.4 · TRUNCATE

sql
TRUNCATE TABLE lineas_pedido;  -- elimina todas las filas (más rápido que DELETE)
!

DROP y TRUNCATE no tienen deshacer en la mayoría de motores. Antes de ejecutarlos fuera de un entorno de pruebas, haz una copia de seguridad.

04

DML — Manipulación de datos

-- insertar, actualizar y borrar filas

4.1 · INSERT

sql
-- Insertar un registro
INSERT INTO clientes (nombre, email, telefono, ciudad)
VALUES ('Ana Pérez', 'ana@email.com', '666111222', 'Madrid');

-- Insertar múltiples registros
INSERT INTO categorias (nombre, descripcion) VALUES
    ('Electrónica', 'Dispositivos electrónicos'),
    ('Ropa', 'Prendas de vestir'),
    ('Hogar', 'Productos para el hogar');

-- Insertar con AUTO_INCREMENT y DEFAULT
INSERT INTO productos (nombre, precio, id_categoria)
VALUES ('Portátil', 800.00, 1);  -- stock toma el valor DEFAULT (0)

4.2 · UPDATE

sql
-- Actualizar un registro específico (SIEMPRE CON WHERE)
UPDATE clientes SET telefono = '677888999', ciudad = 'Barcelona'
WHERE id_cliente = 1;

-- Actualizar múltiples registros
UPDATE productos SET precio = precio * 1.10  -- sube un 10%
WHERE id_categoria = 1;

-- Actualizar con JOIN (MySQL)
UPDATE productos p
JOIN categorias c ON p.id_categoria = c.id_categoria
SET p.stock = p.stock + 50
WHERE c.nombre = 'Electrónica';

4.3 · DELETE

sql
-- Borrar un registro específico (SIEMPRE CON WHERE)
DELETE FROM clientes WHERE id_cliente = 1;

-- Borrar con JOIN (MySQL)
DELETE p FROM productos p
JOIN categorias c ON p.id_categoria = c.id_categoria
WHERE c.nombre = 'Ropa' AND p.stock = 0;

-- Borrar todos los registros (cuidado)
DELETE FROM productos;  -- sin WHERE, borra todo
-- Mejor usar TRUNCATE para vaciar rápido
*

La regla de oro de esta sección: en UPDATE y DELETE, escribe primero el WHERE mentalmente. Un UPDATE sin WHERE afecta a la tabla entera.

05

Consultas básicas (SELECT)

-- el verbo que más vas a escribir en tu vida

5.1 · SELECT básico y filtros

sql
-- Columnas específicas
SELECT nombre, email, ciudad FROM clientes;

-- Alias (AS)
SELECT nombre AS cliente, email AS correo FROM clientes;

-- Filtrar con WHERE
SELECT * FROM productos WHERE precio > 100;
SELECT * FROM clientes WHERE ciudad = 'Madrid' OR ciudad = 'Barcelona';

-- BETWEEN (rango)
SELECT * FROM productos WHERE precio BETWEEN 50 AND 200;

-- IN (lista)
SELECT * FROM clientes WHERE ciudad IN ('Madrid', 'Barcelona', 'Valencia');

-- LIKE (patrón)
SELECT * FROM clientes WHERE email LIKE '%@gmail.com';
SELECT * FROM clientes WHERE nombre LIKE 'A%';

-- IS NULL / IS NOT NULL
SELECT * FROM clientes WHERE telefono IS NULL;

Operadores de comparación disponibles: =!=><>=<=BETWEENINLIKEIS NULL

5.2 · DISTINCT

sql
SELECT DISTINCT ciudad FROM clientes;

5.3 · ORDER BY

sql
SELECT * FROM productos ORDER BY precio DESC;
SELECT * FROM pedidos ORDER BY fecha_pedido DESC, total DESC;

5.4 · LIMIT (paginación)

sql
SELECT * FROM productos LIMIT 10;
SELECT * FROM productos LIMIT 10 OFFSET 10;  -- página 2 (registros 11-20)

5.5 · CASE (lógica condicional)

El equivalente SQL a un if/elif/else: evalúa condiciones en orden y devuelve el primer resultado que encaje.

sql
SELECT nombre, precio,
    CASE
        WHEN precio < 50 THEN 'Económico'
        WHEN precio < 200 THEN 'Normal'
        ELSE 'Caro'
    END AS categoria_precio
FROM productos;
i

Funciones de agregación y GROUP BY

-- de muchas filas a un resumen

6.1 · Funciones agregadas básicas

FunciónDescripciónEjemplo
COUNT(*)Número total de filasSELECT COUNT(*) FROM clientes
COUNT(col)Número de valores no nulosSELECT COUNT(telefono) FROM clientes
COUNT(DISTINCT col)Número de valores distintosSELECT COUNT(DISTINCT ciudad) FROM clientes
SUM(col)Suma de valoresSELECT SUM(total) FROM pedidos
AVG(col)Media de valoresSELECT AVG(precio) FROM productos
MAX(col)Valor máximoSELECT MAX(precio) FROM productos
MIN(col)Valor mínimoSELECT MIN(precio) FROM productos
sql
SELECT
    COUNT(*) AS total_productos,
    AVG(precio) AS precio_medio,
    MAX(precio) AS precio_maximo,
    MIN(precio) AS precio_minimo
FROM productos;

6.2 · GROUP BY

sql
SELECT
    c.nombre AS categoria,
    COUNT(p.id_producto) AS cantidad,
    AVG(p.precio) AS precio_medio
FROM productos p
JOIN categorias c ON p.id_categoria = c.id_categoria
GROUP BY c.id_categoria, c.nombre;

6.3 · HAVING

Igual que WHERE filtra filas, HAVING filtra grupos — por eso puede usar funciones agregadas y siempre va después de GROUP BY.

sql
-- Clientes que han gastado más de 300€
SELECT
    c.nombre,
    SUM(p.total) AS gasto_total
FROM clientes c
JOIN pedidos p ON c.id_cliente = p.id_cliente
GROUP BY c.id_cliente, c.nombre
HAVING SUM(p.total) > 300;

6.4 · Agregación condicional con CASE

sql
SELECT
    SUM(CASE WHEN precio < 50 THEN 1 ELSE 0 END) AS economicos,
    SUM(CASE WHEN precio BETWEEN 50 AND 200 THEN 1 ELSE 0 END) AS normales,
    SUM(CASE WHEN precio > 200 THEN 1 ELSE 0 END) AS caros
FROM productos;

    CONCAT(nombre, ' (', email, ')') AS contacto,
    UPPER(ciudad) AS ciudad_mayus,
    LENGTH(nombre) AS longitud_nombre,
    SUBSTRING(email, 1, LOCATE('@', email)-1) AS usuario_email
FROM clientes;

7.2 · Funciones de fecha y hora

    nombre,
    fecha_alta,
    DATEDIFF(CURDATE(), fecha_alta) AS dias_cliente,
    YEAR(fecha_alta) AS año_alta
FROM clientes;

-- Pedidos del último mes
SELECT * FROM pedidos
WHERE fecha_pedido > DATE_SUB(NOW(), INTERVAL 30 DAY);

7.3 · Manejo de NULL

NULL no es cero ni cadena vacía: es ausencia de valor. Por eso no se compara con =, sino con IS NULL, y por eso existen funciones específicas para sustituirlo por un valor por defecto.

sql
-- COALESCE: devuelve el primer valor no nulo (estándar, funciona en todos los motores)
SELECT
    nombre,
    COALESCE(telefono, 'Sin teléfono') AS telefono,
    COALESCE(ciudad, 'Sin ciudad') AS ciudad
FROM clientes;

-- IFNULL (MySQL) / NVL (Oracle) / ISNULL (SQL Server): equivalentes específicos
SELECT nombre, IFNULL(telefono, 'No disponible') AS telefono FROM clientes;
08

JOINs — combinar tablas

-- reconstruir el mundo real a partir de tablas separadas

Los datos normalizados viven repartidos en varias tablas para evitar duplicación. Un JOIN las vuelve a juntar en el momento de la consulta, según una condición de relación (normalmente PK = FK).

8.1 · INNER JOIN (solo coincidencias)

sql
SELECT p.id_pedido, c.nombre, p.fecha_pedido, p.total
FROM pedidos p
INNER JOIN clientes c ON p.id_cliente = c.id_cliente;

8.2 · LEFT JOIN (todos los de la izquierda)

sql
-- Clientes con o sin pedidos
SELECT c.nombre, COUNT(p.id_pedido) AS num_pedidos
FROM clientes c
LEFT JOIN pedidos p ON c.id_cliente = p.id_cliente
GROUP BY c.id_cliente, c.nombre;

-- Productos que nunca se han vendido
SELECT p.nombre
FROM productos p
LEFT JOIN lineas_pedido lp ON p.id_producto = lp.id_producto
WHERE lp.id_producto IS NULL;

8.3 · RIGHT JOIN

Menos común en la práctica — casi cualquier RIGHT JOIN puede reescribirse como un LEFT JOIN intercambiando el orden de las tablas.

sql
SELECT p.id_pedido, c.nombre
FROM clientes c
RIGHT JOIN pedidos p ON c.id_cliente = p.id_cliente;
-- equivalente a: FROM pedidos p LEFT JOIN clientes c ON ...

8.4 · JOIN múltiple (4 tablas o más)

sql
SELECT
    c.nombre AS cliente,
    p.fecha_pedido,
    pr.nombre AS producto,
    lp.cantidad,
    lp.precio_unitario,
    (lp.cantidad * lp.precio_unitario) AS subtotal
FROM pedidos p
JOIN clientes c ON p.id_cliente = c.id_cliente
JOIN lineas_pedido lp ON p.id_pedido = lp.id_pedido
JOIN productos pr ON lp.id_producto = pr.id_producto
WHERE p.id_pedido = 1;

8.5 · Self-Join

Una tabla puede unirse consigo misma cuando hay una relación jerárquica interna, como una categoría que tiene una categoría padre.

sql
-- Relaciones jerárquicas en categorías (categorías padre-hijo)
ALTER TABLE categorias ADD id_categoria_padre INT;
ALTER TABLE categorias ADD FOREIGN KEY (id_categoria_padre) REFERENCES categorias(id_categoria);

SELECT
    c1.nombre AS subcategoria,
    c2.nombre AS categoria_padre
FROM categorias c1
LEFT JOIN categorias c2 ON c1.id_categoria_padre = c2.id_categoria;

8.6 · NATURAL JOIN

sql
-- Une automáticamente por TODAS las columnas con el mismo nombre
SELECT * FROM pedidos NATURAL JOIN clientes;  -- une por id_cliente
!

NATURAL JOIN es cómodo pero frágil: si añades una columna nueva a cualquiera de las dos tablas con un nombre que coincide por casualidad, la condición de unión cambia sin avisar. En producción, casi siempre es mejor un JOIN ... ON explícito.

09

Subconsultas (básicas y avanzadas)

-- una consulta dentro de otra consulta

9.1 · Subconsulta en WHERE (escalar)

sql
-- Productos más caros que la media
SELECT nombre, precio
FROM productos
WHERE precio > (SELECT AVG(precio) FROM productos);

-- Productos con precio > precio medio de SU categoría (correlacionada)
SELECT p.nombre, p.precio, p.id_categoria
FROM productos p
WHERE p.precio > (
    SELECT AVG(p2.precio)
    FROM productos p2
    WHERE p2.id_categoria = p.id_categoria
);

9.2 · Subconsulta con IN / NOT IN

sql
SELECT nombre FROM clientes
WHERE id_cliente IN (SELECT DISTINCT id_cliente FROM pedidos);

SELECT nombre FROM productos
WHERE id_producto NOT IN (SELECT DISTINCT id_producto FROM lineas_pedido);

9.3 · Subconsulta con EXISTS / NOT EXISTS

EXISTS solo comprueba si la subconsulta devuelve filas — no le importa cuántas ni cuáles — así que suele ser más eficiente que IN sobre tablas grandes.

sql
-- Clientes que han hecho pedidos
SELECT c.nombre
FROM clientes c
WHERE EXISTS (
    SELECT 1 FROM pedidos p
    WHERE p.id_cliente = c.id_cliente
);

-- Clientes que NO han hecho pedidos
SELECT c.nombre
FROM clientes c
WHERE NOT EXISTS (
    SELECT 1 FROM pedidos p
    WHERE p.id_cliente = c.id_cliente
);

9.4 · Subconsulta en FROM (tabla derivada)

sql
SELECT nombre, gasto_total
FROM (
    SELECT
        c.nombre,
        SUM(p.total) AS gasto_total
    FROM clientes c
    JOIN pedidos p ON c.id_cliente = p.id_cliente
    GROUP BY c.id_cliente, c.nombre
) AS resumen_clientes
WHERE gasto_total > 1000;

9.5 · Subconsulta en SELECT (escalar)

sql
SELECT
    c.nombre,
    (SELECT COUNT(*) FROM pedidos p WHERE p.id_cliente = c.id_cliente) AS num_pedidos,
    (SELECT COALESCE(SUM(total), 0) FROM pedidos p WHERE p.id_cliente = c.id_cliente) AS total_gastado
FROM clientes c;

9.6 · Comparación con ANY / ALL

sql
-- Más caros que TODOS los de electrónica
SELECT nombre, precio FROM productos
WHERE precio > ALL (
    SELECT precio FROM productos
    WHERE id_categoria = (SELECT id_categoria FROM categorias WHERE nombre = 'Electrónica')
);

-- Más caros que ALGUNO de electrónica
SELECT nombre, precio FROM productos
WHERE precio > ANY (
    SELECT precio FROM productos
    WHERE id_categoria = (SELECT id_categoria FROM categorias WHERE nombre = 'Electrónica')
);
10

Operadores de conjunto

-- UNION · INTERSECT · EXCEPT

10.1 · UNION

sql
-- Clientes y proveedores en un solo listado
SELECT nombre, email, 'Cliente' AS tipo FROM clientes
UNION
SELECT nombre, email, 'Proveedor' AS tipo FROM proveedores;

-- UNION ALL (incluye duplicados, más rápido)
SELECT nombre, ciudad FROM clientes WHERE ciudad = 'Madrid'
UNION ALL
SELECT nombre, ciudad FROM clientes WHERE ciudad = 'Barcelona';

10.2 · INTERSECT

sql
-- PostgreSQL / SQL Server
SELECT id_producto FROM lineas_pedido
INTERSECT
SELECT id_producto FROM productos WHERE stock > 0;

-- MySQL no tiene INTERSECT: se simula con JOIN
SELECT DISTINCT p.id_producto, p.nombre
FROM productos p
JOIN lineas_pedido lp ON p.id_producto = lp.id_producto
WHERE p.stock > 0;

10.3 · EXCEPT / MINUS

sql
-- PostgreSQL: EXCEPT
SELECT id_producto FROM productos
EXCEPT
SELECT DISTINCT id_producto FROM lineas_pedido;

-- MySQL: se simula con NOT EXISTS
SELECT p.id_producto, p.nombre
FROM productos p
WHERE NOT EXISTS (
    SELECT 1 FROM lineas_pedido lp WHERE lp.id_producto = p.id_producto
);
i

Regla práctica de compatibilidad: MySQL no implementa INTERSECT ni EXCEPT de forma nativa (hasta versiones recientes). PostgreSQL y SQL Server sí. Cuando dudes, la alternativa con JOIN/EXISTS funciona en todos los motores.

11

Funciones de ventana (window functions)

-- calcular sobre un grupo de filas sin colapsarlas en una sola

A diferencia de GROUP BY, una función de ventana no reduce el número de filas: cada fila conserva su identidad, pero gana una columna calculada "mirando" a las filas vecinas definidas por OVER (...).

11.1 · ROW_NUMBER()

sql
SELECT
    nombre, precio,
    ROW_NUMBER() OVER (ORDER BY precio DESC) AS ranking
FROM productos;

-- Con PARTITION BY: reinicia el contador por cada categoría
SELECT
    c.nombre AS categoria,
    p.nombre AS producto,
    p.precio,
    ROW_NUMBER() OVER (PARTITION BY p.id_categoria ORDER BY p.precio DESC) AS posicion_en_categoria
FROM productos p
JOIN categorias c ON p.id_categoria = c.id_categoria;

11.2 · RANK() y DENSE_RANK()

sql
-- RANK(): si hay empate, salta números. DENSE_RANK(): no los salta.
SELECT
    nombre, precio,
    RANK() OVER (ORDER BY precio DESC) AS rank_normal,
    DENSE_RANK() OVER (ORDER BY precio DESC) AS rank_denso
FROM productos;

11.3 · LAG() y LEAD()

sql
-- Comparar con el producto anterior (más barato) en el orden
SELECT
    nombre, precio,
    LAG(precio, 1) OVER (ORDER BY precio) AS precio_anterior,
    precio - LAG(precio, 1) OVER (ORDER BY precio) AS diferencia
FROM productos;

11.4 · SUM() OVER() — acumulados

sql
SELECT
    c.nombre,
    p.fecha_pedido,
    p.total,
    SUM(p.total) OVER (PARTITION BY c.id_cliente ORDER BY p.fecha_pedido) AS acumulado_cliente
FROM pedidos p
JOIN clientes c ON p.id_cliente = c.id_cliente
ORDER BY c.nombre, p.fecha_pedido;

11.5 · NTILE() — cuartiles y percentiles

sql
SELECT
    nombre, precio,
    NTILE(4) OVER (ORDER BY precio) AS cuartil
FROM productos;
*

La consola SQL de esta guía no interpreta OVER (...); es un buen momento para copiar estos ejemplos y probarlos en un SGBD real (MySQL 8+, PostgreSQL o SQL Server) contra tu propia versión de la tabla productos.

12

Vistas (VIEWS)

-- una consulta guardada que se comporta como una tabla

12.1 · Crear vistas

sql
CREATE VIEW resumen_clientes AS
SELECT
    c.id_cliente, c.nombre, c.email,
    COUNT(p.id_pedido) AS total_pedidos,
    COALESCE(SUM(p.total), 0) AS total_gastado,
    COALESCE(AVG(p.total), 0) AS media_pedido
FROM clientes c
LEFT JOIN pedidos p ON c.id_cliente = p.id_cliente
GROUP BY c.id_cliente, c.nombre, c.email;

CREATE VIEW productos_completos AS
SELECT
    p.id_producto, p.nombre AS producto, p.precio, p.stock,
    c.nombre AS categoria,
    GROUP_CONCAT(pr.nombre SEPARATOR ', ') AS proveedores
FROM productos p
JOIN categorias c ON p.id_categoria = c.id_categoria
LEFT JOIN productos_proveedores pp ON p.id_producto = pp.id_producto
LEFT JOIN proveedores pr ON pp.id_proveedor = pr.id_proveedor
GROUP BY p.id_producto;

12.2 · Usar vistas (como tablas)

sql
SELECT * FROM resumen_clientes WHERE total_gastado > 1000;
SELECT * FROM productos_completos WHERE categoria = 'Electrónica';

12.3 · Actualizar a través de una vista

Solo funciona si la vista es "actualizable": sin JOINs complejos ni agregación, y basada en una única tabla base.

sql
CREATE VIEW clientes_activos AS
SELECT * FROM clientes WHERE activo = TRUE;

UPDATE clientes_activos SET ciudad = 'Sevilla' WHERE id_cliente = 1;

12.4 · Eliminar vista

sql
DROP VIEW resumen_clientes;

Índices y rendimiento

-- el índice de un libro, aplicado a una tabla

13.1 · Tipos de índices

  • INDEX (B-tree): búsqueda rápida por valor
  • UNIQUE INDEX: índice que además obliga a valores únicos
  • FULLTEXT: búsqueda de texto completo
  • SPATIAL: datos geoespaciales

13.2 · Crear índices

sql
CREATE INDEX idx_nombre ON clientes(nombre);
CREATE INDEX idx_ciudad_nombre ON clientes(ciudad, nombre);   -- compuesto
CREATE UNIQUE INDEX idx_email ON clientes(email);
CREATE FULLTEXT INDEX idx_descripcion ON productos(descripcion);

13.3 · EXPLAIN — analizar consultas

sql
EXPLAIN SELECT * FROM clientes WHERE nombre = 'Ana Pérez';
-- Muestra: tipo de búsqueda, uso de índice, coste estimado

EXPLAIN SELECT c.nombre, SUM(p.total)
FROM clientes c
JOIN pedidos p ON c.id_cliente = p.id_cliente
WHERE c.ciudad = 'Madrid'
GROUP BY c.id_cliente;

13.4 · Cuándo usar índices

Usar índices en…No usar índices en…
Columnas en WHEREColumnas con pocos valores distintos (ej. sexo)
Columnas en JOINTablas muy pequeñas
Columnas en ORDER BYColumnas que cambian mucho (ej. stock)
Columnas con UNIQUEColumnas con muchos NULL
*

Un índice acelera la lectura pero ralentiza INSERT/UPDATE/DELETE, porque el índice también hay que mantenerlo. No indexes "por si acaso".

Transacciones y control de errores

-- todo o nada

14.1 · Conceptos ACID

Atomicity

Todo o nada: si una parte falla, se deshace la transacción completa.

Consistency

La base pasa de un estado válido a otro estado válido.

Isolation

Las transacciones concurrentes no se pisan entre sí.

Durability

Una vez confirmados, los cambios sobreviven a un fallo del sistema.

14.2 · Comandos básicos

sql
START TRANSACTION;              -- iniciar
COMMIT;                         -- confirmar cambios
ROLLBACK;                       -- deshacer todo
SAVEPOINT nombre;               -- punto de guardado parcial
ROLLBACK TO SAVEPOINT nombre;   -- volver a ese punto

14.3 · Ejemplo práctico (pedido con líneas)

sql
START TRANSACTION;

INSERT INTO pedidos (id_cliente, fecha_pedido) VALUES (1, NOW());
SET @id_pedido = LAST_INSERT_ID();

INSERT INTO lineas_pedido (id_pedido, id_producto, cantidad, precio_unitario)
VALUES
    (@id_pedido, 1, 2, 50.00),
    (@id_pedido, 2, 1, 120.00);

UPDATE productos SET stock = stock - 2 WHERE id_producto = 1;
UPDATE productos SET stock = stock - 1 WHERE id_producto = 2;

COMMIT;

14.4 · SAVEPOINT (recuperación parcial)

sql
START TRANSACTION;

INSERT INTO pedidos (id_cliente) VALUES (1);
SAVEPOINT pedido_creado;

UPDATE productos SET stock = stock - 100 WHERE id_producto = 1;  -- puede fallar

ROLLBACK TO SAVEPOINT pedido_creado;  -- deshace solo la última operación

INSERT INTO lineas_pedido (id_pedido, id_producto, cantidad)
VALUES (LAST_INSERT_ID(), 2, 1);

COMMIT;  -- solo se guardan la operación 1 y la 3

14.5 · Manejo de errores (MySQL, procedimiento)

sql
DELIMITER //
CREATE PROCEDURE hacer_pedido(IN p_id_cliente INT, IN p_id_producto INT, IN p_cantidad INT)
BEGIN
    DECLARE EXIT HANDLER FOR SQLEXCEPTION
    BEGIN
        ROLLBACK;
        SELECT 'Error en la transacción' AS mensaje;
    END;

    START TRANSACTION;
    INSERT INTO pedidos (id_cliente) VALUES (p_id_cliente);
    SET @id_pedido = LAST_INSERT_ID();
    INSERT INTO lineas_pedido (id_pedido, id_producto, cantidad, precio_unitario)
    SELECT @id_pedido, p_id_producto, p_cantidad, precio FROM productos WHERE id_producto = p_id_producto;
    UPDATE productos SET stock = stock - p_cantidad WHERE id_producto = p_id_producto;
    COMMIT;
    SELECT 'Pedido completado' AS mensaje;
END //
DELIMITER ;

DDL y modelado completo

Enunciado: Diseña y crea la tabla proveedores y la tabla intermedia productos_proveedores (relación N:N). Incluye: PK compuesta, FK, un CHECK para que el email contenga '@', y DEFAULT para la fecha de alta.

CREATE TABLE proveedores (

CREATE TABLE productos_proveedores (

    FOREIGN KEY (id_proveedor) REFERENCES proveedores(id_proveedor)
);

Consultas con funciones

Enunciado: Muestra el nombre de los clientes, su email en minúsculas, los años que llevan como clientes, y su ciudad en mayúsculas. Ordena por antigüedad (más antiguos primero).

▾ ver pista
Usa DATEDIFF, UPPER, LOWER y ORDER BY.
sql
SELECT
    nombre,
    LOWER(email) AS email_minusculas,
    UPPER(ciudad) AS ciudad_mayus,
    DATEDIFF(CURDATE(), fecha_alta) AS dias_cliente,
    ROUND(DATEDIFF(CURDATE(), fecha_alta) / 365, 1) AS años_cliente
FROM clientes
ORDER BY fecha_alta ASC;
3

GROUP BY y HAVING avanzado

Enunciado: Obtén por categoría: número de productos, precio mínimo, máximo, medio, y el número de productos con stock > 0. Muestra solo categorías con más de 3 productos.

▾ ver pista
Usa COUNT, MIN, MAX, AVG, SUM(CASE WHEN...), GROUP BY, HAVING.
sql
SELECT
    c.nombre AS categoria,
    COUNT(p.id_producto) AS total_productos,
    MIN(p.precio) AS precio_minimo,
    MAX(p.precio) AS precio_maximo,
    AVG(p.precio) AS precio_medio,
    SUM(CASE WHEN p.stock > 0 THEN 1 ELSE 0 END) AS productos_con_stock
FROM productos p
JOIN categorias c ON p.id_categoria = c.id_categoria
GROUP BY c.id_categoria, c.nombre
HAVING COUNT(p.id_producto) > 3
ORDER BY total_productos DESC;
4

JOIN múltiple y self-join

Enunciado: Crea una jerarquía de categorías (añade id_categoria_padre). Inserta categorías padre e hijas. Muestra cada subcategoría con su categoría padre y el número de productos que tiene.

▾ ver pista
Self-join para obtener padre-hijo, luego JOIN con productos y GROUP BY.
sql
-- Paso 1: modificar tabla
ALTER TABLE categorias ADD id_categoria_padre INT;
ALTER TABLE categorias ADD FOREIGN KEY (id_categoria_padre) REFERENCES categorias(id_categoria);

-- Paso 2: datos de ejemplo
INSERT INTO categorias (nombre, descripcion) VALUES
    ('Electrónica', 'Productos electrónicos'), ('Ropa', 'Prendas de vestir');
INSERT INTO categorias (nombre, descripcion, id_categoria_padre) VALUES
    ('Ordenadores', 'PCs y portátiles', 1), ('Smartphones', 'Teléfonos móviles', 1);

-- Paso 3: consulta final
SELECT
    h.nombre AS subcategoria,
    p.nombre AS categoria_padre,
    COUNT(pr.id_producto) AS num_productos
FROM categorias h
LEFT JOIN categorias p ON h.id_categoria_padre = p.id_categoria
LEFT JOIN productos pr ON pr.id_categoria = h.id_categoria
WHERE h.id_categoria_padre IS NOT NULL
GROUP BY h.id_categoria, h.nombre, p.nombre;

Subconsultas con EXISTS y NOT EXISTS

Enunciado: Encuentra los clientes que han hecho pedidos en el último mes (con EXISTS) y los que NO han hecho ningún pedido en el último año (con NOT EXISTS).

▾ ver pista
Usa DATE_SUB(NOW(), INTERVAL 1 MONTH) y DATE_SUB(NOW(), INTERVAL 1 YEAR).
sql
-- Clientes con pedidos en el último mes
SELECT c.nombre, c.email FROM clientes c
WHERE EXISTS (
    SELECT 1 FROM pedidos p
    WHERE p.id_cliente = c.id_cliente
    AND p.fecha_pedido >= DATE_SUB(NOW(), INTERVAL 1 MONTH)
);

-- Clientes sin pedidos en el último año
SELECT c.nombre, c.email FROM clientes c
WHERE NOT EXISTS (
    SELECT 1 FROM pedidos p
    WHERE p.id_cliente = c.id_cliente
    AND p.fecha_pedido >= DATE_SUB(NOW(), INTERVAL 1 YEAR)
);
6

Funciones de ventana

Enunciado: Para cada producto, muestra su categoría, precio, el ranking de precio dentro de su categoría (RANK()), y la diferencia con el producto inmediatamente más barato de la misma categoría (LAG()).

▾ ver pista
Usa RANK() OVER (PARTITION BY ... ORDER BY ...) y LAG(precio) OVER (PARTITION BY ... ORDER BY ...).
sql
SELECT
    c.nombre AS categoria,
    p.nombre AS producto,
    p.precio,
    RANK() OVER (PARTITION BY p.id_categoria ORDER BY p.precio DESC) AS ranking_categoria,
    LAG(p.precio, 1) OVER (PARTITION BY p.id_categoria ORDER BY p.precio DESC) AS precio_anterior_mas_caro,
    (LAG(p.precio, 1) OVER (PARTITION BY p.id_categoria ORDER BY p.precio DESC) - p.precio) AS diferencia_con_anterior
FROM productos p
JOIN categorias c ON p.id_categoria = c.id_categoria
ORDER BY c.nombre, p.precio DESC;

Transacciones con SAVEPOINT

Enunciado: Escribe una transacción que inserte un pedido para el cliente 1, inserte 2 líneas de pedido, actualice el stock, y si el stock de algún producto queda negativo, haga ROLLBACK al SAVEPOINT anterior a la actualización.

▾ ver pista
Crea un SAVEPOINT después de insertar las líneas y antes de actualizar el stock. Si stock < 0, ROLLBACK TO ese savepoint.
sql
START TRANSACTION;

INSERT INTO pedidos (id_cliente, fecha_pedido) VALUES (1, NOW());
SET @id_pedido = LAST_INSERT_ID();

INSERT INTO lineas_pedido (id_pedido, id_producto, cantidad, precio_unitario)
VALUES
    (@id_pedido, 1, 2, (SELECT precio FROM productos WHERE id_producto = 1)),
    (@id_pedido, 2, 1, (SELECT precio FROM productos WHERE id_producto = 2));

SAVEPOINT antes_stock;

UPDATE productos SET stock = stock - 2 WHERE id_producto = 1;
UPDATE productos SET stock = stock - 1 WHERE id_producto = 2;

IF (SELECT COUNT(*) FROM productos WHERE stock < 0) > 0 THEN
    ROLLBACK TO SAVEPOINT antes_stock;
    SELECT 'Error: stock insuficiente' AS mensaje;
ELSE
    COMMIT;
    SELECT 'Pedido completado' AS mensaje;
END IF;

Índices y EXPLAIN

Enunciado: Crea un índice en email de clientes y otro compuesto en (ciudad, nombre). Usa EXPLAIN para analizar una consulta que busque por ciudad = 'Madrid' y nombre LIKE 'A%'. Compara el plan con y sin índices.

▾ ver pista
Usa CREATE INDEX, EXPLAIN SELECT ... y DROP INDEX para comparar.
sql
CREATE INDEX idx_email ON clientes(email);

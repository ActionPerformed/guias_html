Tu propia nube: Nextcloud sobre LEMP en Docker

2º ASIR · Implantación de aplicaciones web · 8 h (4 sesiones) · Host Windows 11 + Docker Desktop (WSL 2)

«¿Qué tendría que hacer si no tuviera Docker?»

1 · Presentación

Nextcloud integra archivos, calendario, contactos, tareas y edición colaborativa, pero en tu infraestructura: control total sobre datos y seguridad. Vas a desplegarlo, comprender qué necesita por debajo, configurarlo para una intranet, gestionar usuarios y asegurarlo. Cada vez que Docker resuelva algo por ti, mirarás dentro y contrastarás lo que Docker hace con lo que harías a mano.

Windows 11 como host: 1) comandos en PowerShell; 2) los volúmenes viven dentro de la VM de WSL 2, no en C:\; 3) para acceder desde otros equipos hay que abrir el puerto en el Firewall y configurar trusted domains; 4) el .env se protege con icacls, no con chmod.
Debes entregar capturas de cada paso, mostrando el comando y el resultado.

4.1 · Verificar WSL 2 y Docker Desktop

wsl --version
docker --version
docker compose version

WSL debe ser 2.1.5 o superior; si no, wsl --update (PowerShell como administrador). En Docker Desktop → Settings → General, marca Use WSL 2 based engine.

wsl --version (≥ 2.1.5) y docker --version + docker compose version.
Docker no arranca: revisa la virtualización en BIOS/UEFI. Si wsl --version da error: wsl --install y reinicia.

4.2 · Carpeta de trabajo y .env

mkdir C:\ASIR\nextcloud-lab
cd C:\ASIR\nextcloud-lab
El Bloc de notas puede guardar .env.txt. Comprueba con dir /a que se llama exactamente .env.
# .env — NO compartir, NO subir a git
MYSQL_ROOT_PASSWORD=root_cambiame_por_una_segura
MYSQL_DATABASE=nextcloud
MYSQL_USER=nextcloud
MYSQL_PASSWORD=nextcloud_cambiame_por_una_segura
NEXTCLOUD_ADMIN_USER=admin
NEXTCLOUD_ADMIN_PASSWORD=admin_cambiame_por_una_segura
NEXTCLOUD_TRUSTED_DOMAINS=localhost 127.0.0.1

Cambia los valores por frases largas y aleatorias. NEXTCLOUD_TRUSTED_DOMAINS lleva espacios porque es una lista separada por espacios.

icacls .env /inheritance:r
icacls .env /grant:r "$($env:USERNAME):(R,W)"
icacls .env

Primero se elimina la herencia; luego solo tu usuario recibe lectura/escritura. No debe aparecer Users ni Everyone.

".env" | Out-File -Encoding ascii -Append .gitignore
.env censurado, icacls .env y .gitignore con la línea .env.

4.3 · compose.yaml

Es un punto de partida: debes justificar cada decisión (¿por qué MariaDB 11? ¿volúmenes nombrados? ¿red bridge explícita? ¿la BD sin puertos? ¿credenciales como ${VARIABLE}?).

services:
  db:
    image: mariadb:11
    restart: unless-stopped
    environment:
      MYSQL_ROOT_PASSWORD: ${MYSQL_ROOT_PASSWORD}
      MYSQL_DATABASE: ${MYSQL_DATABASE}
      MYSQL_USER: ${MYSQL_USER}
      MYSQL_PASSWORD: ${MYSQL_PASSWORD}
    volumes:
      - db_data:/var/lib/mysql
    networks:
      - nextcloud-net

  app:
    image: nextcloud:apache
    restart: unless-stopped
    ports:
      - "8080:80"
    environment:
      MYSQL_HOST: db
      MYSQL_DATABASE: ${MYSQL_DATABASE}
      MYSQL_USER: ${MYSQL_USER}
      MYSQL_PASSWORD: ${MYSQL_PASSWORD}
      NEXTCLOUD_ADMIN_USER: ${NEXTCLOUD_ADMIN_USER}
      NEXTCLOUD_ADMIN_PASSWORD: ${NEXTCLOUD_ADMIN_PASSWORD}
      NEXTCLOUD_TRUSTED_DOMAINS: ${NEXTCLOUD_TRUSTED_DOMAINS}
    volumes:
      - nextcloud_data:/var/www/html
    depends_on:
      - db
    networks:
      - nextcloud-net

volumes:
  db_data:
  nextcloud_data:

networks:
  nextcloud-net:
    driver: bridge
Debes poder justificar: db no publica puertos (menos superficie de ataque) · los volúmenes persisten aunque se recreen los contenedores · 8080:80 publica el 80 del contenedor en el 8080 del host (si está ocupado, cámbialo y documéntalo) · el compose no contiene contraseñas en claro.
depends_on solo garantiza el orden de arranque, no que MariaDB esté lista. ¿Qué crees que pasa si Nextcloud arranca antes que la BD?
nextcloud:apache y mariadb:11 son etiquetas «móviles»: ¿qué ventaja daría fijar una versión concreta para reproducir la práctica?

S3Intranet, usuarios y seguridad

6.1 · Trusted domains y firewall (criterio d)

En Windows son dos barreras distintas: el firewall decide si el paquete llega; Nextcloud decide si acepta el nombre/IP usado. Averigua tu IPv4 con ipconfig y pruébalo en el simulador:

Marca las barreras y lanza la petición…

New-NetFirewallRule -DisplayName "Nextcloud 8080" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 8080

(PowerShell como administrador). Verificación: Get-NetFirewallRule -DisplayName "Nextcloud 8080"; el compañero abre http://TU_IP:8080.

Importante: NEXTCLOUD_TRUSTED_DOMAINS solo se aplica en la primera instalación. Como el volumen ya contiene config.php, editar el .env y hacer down/up normalmente no añadirá tu IP (aunque restart tampoco recarga el .env). Comprueba el resultado real y, si falta, añádela con occ: 
docker compose exec app php occ config:system:get trusted_domains
docker compose exec -u www-data app php occ config:system:set trusted_domains 2 --value=192.168.1.50
Lección: tras instalar, la fuente de verdad es config.php, no el .env. Si el aula está clasificada como red Pública, la regla también debe cubrir ese perfil.
trusted_domains con tu IP, regla de firewall y acceso desde otro equipo.
Documenta: ¿qué ocurre sin trusted domains? ¿Y sin regla de firewall? ¿Por qué son pasos separados?

6.3 · Seguridad de acceso (criterio f)

  1. Política de contraseñas (Administración → Seguridad): mínimo 10, mayúsculas, minúsculas, números y especiales; intenta crear un usuario con clave débil. (Si no aparece, comprueba que la app Password policy está habilitada.)
  2. 2FA forzado: activa Two-Factor TOTP Provider y fuérzalo para el grupo profesores.
  3. Advertencias (Administración → Información general): documenta al menos dos y cómo las resolverías.
  4. HTTPS en producción (documentado, no ejecutado): certbot/Let's Encrypt, config Apache/Nginx, redirección 301, HSTS.
  5. .env en Windows: por qué icacls y no chmod, y qué riesgo supone que alguien lo lea.
El admin no está en profesores, así que no se queda fuera. Aprende la regla: nunca fuerces 2FA a quien administra sin haber probado antes. Para ana.garcia necesitarás una app TOTP y guarda los códigos de respaldo; en S4, los clientes externos (escritorio, CalDAV) deberán usar una contraseña de aplicación.

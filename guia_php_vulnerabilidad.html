BWordPress con image:

      
El problema: etiqueta oficial pero congelada

      
services:
  wordpress:
    image: wordpress:6-php8.3-fpm   # ¡publicada hace ~5 meses, PHP 8.3.31!

      
La etiqueta pertenece a la imagen oficial (library/wordpress), pero Docker ya no la reconstruye
        con los nuevos parches de PHP porque la rama activa es otra.

      
Por qué build no sirve aquí

      
docker compose build --pull --no-cache
WARN[0000] No services to build

      
El servicio solo tiene image:, no build:. La advertencia es
        inofensiva, pero te avisa de que necesitas otro mecanismo: descargar, no compilar.

      
Cómo actualizar una imagen prefabricada

      
docker compose pull
docker compose up -d --force-recreate

      
Si sospechas de caché local:

      
docker compose down
docker rmi wordpress:6-php8.3-fpm
docker compose pull wordpress
docker compose up -d

      
La solución real: una etiqueta oficial mantenida

      
Las etiquetas activas ya son de la rama 7. Cambia a una etiqueta mantenida:

      
image: wordpress:7-php8.3-fpm   # o fija: wordpress:7.1-php8.3-fpm

      
El volumen wordpress_data y la base de datos se mantienen intactos: no pierdes
        contenido. Verifica con docker compose exec wordpress php -v; debe salir PHP 8.3.36 o superior.
      

    


    

      
Docker Hub y etiquetas

      

        

          
Imagen oficial

          
Sin prefijo de usuario: wordpress, php, mariadb. URL:
            hub.docker.com/_/wordpress (internamente library/).

        

        

          
Imagen de la comunidad

          
Con prefijo de usuario: festum/wordpress. URL: hub.docker.com/r/festum/wordpress.

¿Está mantenida esta etiqueta?

      
Ser oficial no garantiza estar mantenida. Mira el campo Last pushed en Docker Hub. Desliza para simular
        su antigüedad:

      
      

      

      

        Los tres sitios donde mirar en Docker Hub
        

          
Nombre: sin prefijo de usuario significa oficial.
Last pushed: si tiene meses o años, esa
            etiqueta ya no recibe parches.
Pestaña Tags: muestra las etiquetas activas. Si la tuya no aparece,
            probablemente esté obsoleta.

          
Listar etiquetas desde PowerShell:

          
Invoke-RestMethod -Uri "https://hub.docker.com/v2/repositories/library/wordpress/tags?page_size=100"

Etiquetas

          
Las flotantes solo reciben parches si el mantenedor reconstruye. Comprueba Last pushed. Ser oficial
            no basta.

        

        

          
Cada servicio, su receta

          
PHP-FPM: fija versión y --pull --no-cache. WordPress: etiqueta mantenida, pull y
            --force-recreate.

        

      

      
Siempre: entorno de pruebas, copia del volumen y de la base de datos, y revisión de
        plugins y temas antes de dar el salto.

Conceptos fundamentales

▾

4.1. ¿Qué es DataStore?

Es la librería moderna de Android para persistir datos clave-valor (reemplaza a SharedPreferences). Ventajas:

  • Asíncrona: no bloquea el hilo principal.
  • Reactiva: expone los datos como Flow, así que la UI se actualiza sola.
  • Sin errores de tipo: no hay ClassCastException como en SharedPreferences.

Uso típico: guardar preferencias del usuario (tema, idioma, sesión...). En esta actividad guardamos el email del usuario y el flag «Recordar sesión».

4.2. ¿Qué es Room?

Room es un ORM (Object-Relational Mapping) sobre SQLite. Convierte clases Kotlin en tablas y consultas SQL en métodos de Kotlin.

Clase Kotlin que representa una tabla.

Entidad
@Entity(tableName = "videojuegos")
data class Videojuego( /* ... */ )

Interfaz con las operaciones (insert, update, delete, query).

DAO
@Dao
interface VideojuegoDao {
    @Query("SELECT * FROM videojuegos ORDER BY titulo ASC")
    fun getAll(): Flow<List<Videojuego>>
}

Clase abstracta que une entidades y DAOs.

Base de datos
@Database(entities = [Videojuego::class], version = 1, exportSchema = false)
abstract class AppDatabase : RoomDatabase() { /* ... */ }

Ventajas sobre SQLite «a pelo»:

  • Type-safe: los errores de SQL se detectan en compilación.
  • Reactivo: las consultas pueden devolver Flow, que emite cambios automáticamente.
  • Menos código: no hay que escribir Cursor, ContentValues, etc.

4.3. ¿Qué es un ViewModel y por qué lo necesitamos?

Un ViewModel sobrevive a los cambios de configuración (rotaciones, cambios de tema), contiene la lógica de negocio (no la UI), expone estado a la UI mediante StateFlow y se destruye solo cuando la pantalla se elimina definitivamente.

El problema que resuelve: en Android, cuando el usuario rota la pantalla, la Activity se destruye y se vuelve a crear. Si la lógica vive en el composable, se reinicia en cada rotación (pierdes el estado, vuelves a cargar datos...). El ViewModel sobrevive a eso.

Analogía: el ViewModel es como el camarero de un restaurante. La UI es el cliente. El cliente pide «tráeme la carta»; el camarero va a la cocina (repositorio), trae los datos y se los da. Si el cliente se cambia de mesa (rota la pantalla), el camarero sigue siendo el mismo. Compruébalo:

Es una capa intermedia entre la UI y las fuentes de datos. Centraliza el acceso a los datos y oculta de dónde vienen (Room, DataStore, API...). Ventaja: si mañana cambias Room por una API, la UI no se entera. Toca cada capa:

4.5. ¿Qué es Flow y StateFlow?

  • Flow → stream de datos asíncrono. Emite valores a lo largo del tiempo.
  • StateFlow → Flow con un valor actual. Ideal para exponer estado a la UI.
Diferencia clave: un Flow puede no emitir nada; un StateFlow siempre tiene un valor actual. En Room, las consultas devuelven Flow<List<T>>: cada vez que la tabla cambia, Room emite una nueva lista y la UI se actualiza sola. (Míralo en el laboratorio: cada operación registra «Flow emite lista».)

4.6. Ciclo de vida en Compose + ViewModel

Componente Cuándo se crea Cuándo se destruye
Activity Al arrancar Al cerrar o rotar (se recrea)
Composable Al entrar en composición Al salir de composición
ViewModel Al pedirlo con viewModel() Al destruirse la pantalla definitivamente
Importante: el ViewModel sobrevive a la rotación. Por eso el estado no se pierde.

5.2. Crear SessionDataStore.kt

Archivo nuevo: app/src/main/java/com/ejemplo/login/SessionDataStore.kt

SessionDataStore.kt
package com.ejemplo.login

import android.content.Context
import androidx.datastore.core.DataStore
import androidx.datastore.preferences.core.Preferences
import androidx.datastore.preferences.core.booleanPreferencesKey
import androidx.datastore.preferences.core.edit
import androidx.datastore.preferences.core.stringPreferencesKey
import androidx.datastore.preferences.preferencesDataStore
import kotlinx.coroutines.flow.Flow
import kotlinx.coroutines.flow.map

// ---------------------------------------------------------
// Extensión sobre Context para obtener el DataStore.
// Se declara una sola vez por proceso (por eso es `val` de extensión).
// ---------------------------------------------------------
private val Context.dataStore: DataStore<Preferences> by preferencesDataStore(
    name = "session_prefs"
)

// ---------------------------------------------------------
// Claves de las preferencias que vamos a guardar.
// ---------------------------------------------------------
private val KEY_EMAIL = stringPreferencesKey("email")
private val KEY_REMEMBER = booleanPreferencesKey("remember_session")

class SessionDataStore(private val context: Context) {

    // ---------------------------------------------------------
    // Lectura: exponemos el email como Flow<String>.
    // Si no hay nada guardado, devuelve "".
    // ---------------------------------------------------------
    val emailFlow: Flow<String> = context.dataStore.data
        .map { prefs -> prefs[KEY_EMAIL] ?: "" }

    // ---------------------------------------------------------
    // Lectura: ¿el usuario marcó "Recordar sesión"?
    // ---------------------------------------------------------
    val rememberFlow: Flow<Boolean> = context.dataStore.data
        .map { prefs -> prefs[KEY_REMEMBER] ?: false }

    // ---------------------------------------------------------
    // Escritura: guarda el email y el flag de "recordar".
    // Se llama desde una corrutina.
    // ---------------------------------------------------------
    suspend fun saveSession(email: String, remember: Boolean) {
        context.dataStore.edit { prefs ->
            prefs[KEY_EMAIL] = email
            prefs[KEY_REMEMBER] = remember
        }
    }

    // ---------------------------------------------------------
    // Borrado: limpia la sesión (al cerrar sesión).
    // ---------------------------------------------------------
    suspend fun clearSession() {
        context.dataStore.edit { prefs ->
            prefs.remove(KEY_EMAIL)
            prefs.remove(KEY_REMEMBER)
        }
    }
}

Código nuevo completo de NavGraph.kt (usa los atajos para saltar entre bloques):

NavGraph.kt
package com.ejemplo.login

import androidx.compose.runtime.Composable
import androidx.compose.runtime.collectAsState
import androidx.compose.runtime.getValue
import androidx.compose.runtime.remember
import androidx.compose.runtime.rememberCoroutineScope
import androidx.compose.ui.platform.LocalContext
import androidx.lifecycle.viewmodel.compose.viewModel
import androidx.navigation.compose.NavHost
import androidx.navigation.compose.composable
import androidx.navigation.compose.rememberNavController
import kotlinx.coroutines.launch

// ---------------------------------------------------------
// Definimos las rutas como constantes para evitar errores tipográficos.
// ---------------------------------------------------------
object Routes {
    const val LOGIN = "login"
    const val REGISTER = "register"
    const val HOME = "home"
}

@Composable
fun AppNavGraph() {
    val navController = rememberNavController()
    val context = LocalContext.current
    val session = SessionDataStore(context)
    val scope = rememberCoroutineScope()

    // ---------------------------------------------------------
    // Base de datos y repositorio.
    //
    // remember { } evita recrear el repositorio en cada recomposición.
    // AppDatabase.getInstance es un singleton, así que siempre devuelve
    // la misma instancia.
    // ---------------------------------------------------------
    val repository = remember {
        val db = AppDatabase.getInstance(context)
        VideojuegoRepository(db.videojuegoDao(), session)
    }

    // ---------------------------------------------------------
    // AUTO-LOGIN: leemos el flag "remember" de DataStore ANTES de
    // componer el NavHost. collectAsState(initial = null) devuelve
    // null mientras no llega el primer valor, y luego el valor real.
    //
    // Mientras sea null, no componemos nada (pantalla en blanco).
    // Es un instante muy breve.
    // ---------------------------------------------------------
    val rememberSession by session.rememberFlow.collectAsState(initial = null)

    // Si aún no sabemos si hay sesión guardada, no componemos el NavHost.
    if (rememberSession == null) return

    // Si el usuario marcó "Recordar sesión", arrancamos en Home.
    // Si no, en Login.
    val startDestination = if (rememberSession == true) Routes.HOME else Routes.LOGIN

    NavHost(
        navController = navController,
        startDestination = startDestination
    ) {
        // --- LOGIN ---
        composable(Routes.LOGIN) {
            LoginScreen(
                onLoginSuccess = { email, remember ->
                    scope.launch {
                        session.saveSession(email, remember)
                        navController.navigate(Routes.HOME) {
                            popUpTo(Routes.LOGIN) { inclusive = true }
                        }
                    }
                },
                onGoToRegister = {
                    navController.navigate(Routes.REGISTER)
                }
            )
        }

        // --- REGISTRO ---
        composable(Routes.REGISTER) {
            RegisterScreen(
                onRegisterSuccess = { email ->
                    scope.launch {
                        session.saveSession(email, remember = true)
                        navController.navigate(Routes.HOME) {
                            popUpTo(Routes.LOGIN) { inclusive = true }
                        }
                    }
                },
                onBackToLogin = {
                    navController.popBackStack()
                }
            )
        }

        // --- HOME ---
        composable(Routes.HOME) {
            // La factory construye el ViewModel con el repositorio.
            val factory = remember { VideojuegoViewModelFactory(repository) }
            val viewModel: VideojuegoViewModel = viewModel(factory = factory)

            HomeScreen(
                viewModel = viewModel,
                onLogout = {
                    scope.launch {
                        session.clearSession()
                        navController.navigate(Routes.LOGIN) {
                            popUpTo(0) { inclusive = true }
                        }
                    }
                }
            )
        }
    }
}

Videojuego.kt
package com.ejemplo.login

import androidx.room.Entity
import androidx.room.PrimaryKey

// ---------------------------------------------------------
// ENTIDAD: representa una fila de la tabla "videojuegos".
// Room genera automáticamente la tabla a partir de esta clase.
// ---------------------------------------------------------
@Entity(tableName = "videojuegos")
data class Videojuego(
    @PrimaryKey(autoGenerate = true)
    val id: Int = 0,                  // 0 = Room asigna el ID automáticamente

    val titulo: String,
    val plataforma: String,           // "PS5", "Switch", "PC"...
    val genero: String,               // "RPG", "Aventura", "Shooter"...
    val anyo: Int,                    // 1998, 2023...
    val nota: Float,                  // 1.0 a 10.0
    val completado: Boolean = false   // ¿Lo has terminado?
)

🔎 De la clase a la tabla: toca un campo y mira en qué columna SQL se convierte.

Kotlin (data class)

val id: Int = 0
val titulo: String
val plataforma: String
val genero: String
val anyo: Int
val nota: Float
val completado: Boolean = false

SQL (conceptual)

id INTEGER PRIMARY KEY AUTOINCREMENT NOT NULL@PrimaryKey(autoGenerate = true): Room lo genera
titulo TEXT NOT NULL
plataforma TEXT NOT NULL
genero TEXT NOT NULL
anyo INTEGER NOT NULL
nota REAL NOT NULL
completado INTEGER NOT NULLBoolean → 0 / 1

Representación orientativa: la tabla se llama videojuegos (por @Entity(tableName = "videojuegos")).

Conceptos clave:

  • @Entity(tableName = "videojuegos") → le dice a Room que esta clase es una tabla.
  • @PrimaryKey(autoGenerate = true) → el campo id es la clave primaria y Room lo genera solo. Por eso id = 0 por defecto.
  • data class → Room necesita que sea data class para generar el código.
  • Tipos soportados nativamente: Int, Long, Float, Double, Boolean, String.

// ---------------------------------------------------------
@Dao
interface VideojuegoDao {

    // ---------------------------------------------------------
    // LECTURA: devuelve todos los videojuegos como Flow.
    // Flow hace que la UI se actualice automáticamente
    // cuando cambia la tabla (consulta reactiva).
    // ---------------------------------------------------------
    @Query("SELECT * FROM videojuegos ORDER BY titulo ASC")
    fun getAll(): Flow<List<Videojuego>>

    // ---------------------------------------------------------
    // LECTURA: un videojuego por ID.
    // ---------------------------------------------------------
    @Query("SELECT * FROM videojuegos WHERE id = :id")
    fun getById(id: Int): Flow<Videojuego?>

    // ---------------------------------------------------------
    // ESCRITURA: insertar un videojuego nuevo.
    // ---------------------------------------------------------
    @Insert
    suspend fun insert(videojuego: Videojuego)

    // ---------------------------------------------------------
    // ESCRITURA: actualizar un videojuego existente.
    // ---------------------------------------------------------
    @Update
    suspend fun update(videojuego: Videojuego)

    // ---------------------------------------------------------
    // ESCRITURA: borrar un videojuego.
    // ---------------------------------------------------------
    @Delete
    suspend fun delete(videojuego: Videojuego)

    // ---------------------------------------------------------
    // ESCRITURA: borrar todos (útil para pruebas).
    // ---------------------------------------------------------
    @Query("DELETE FROM videojuegos")
    suspend fun deleteAll()
}
  • @Dao → interfaz que Room implementa.
  • Flow<List<Videojuego>> → consulta reactiva. Cada vez que la tabla cambia, Room emite una nueva lista.
  • suspend → las operaciones de escritura son suspend porque Room las ejecuta fuera del hilo principal.

// Room genera la implementación.

@Database(
    entities = [Videojuego::class],
    version = 1,
    exportSchema = false
)
abstract class AppDatabase : RoomDatabase() {

    // ---------------------------------------------------------
    // Expone el DAO para poder usarlo desde fuera.
    // ---------------------------------------------------------
    abstract fun videojuegoDao(): VideojuegoDao

    // ---------------------------------------------------------
    // Companion object: patrón Singleton.
    // Solo debe existir UNA instancia de la base de datos en toda la app.
    // ---------------------------------------------------------
    companion object {
        @Volatile
        private var INSTANCE: AppDatabase? = null

        fun getInstance(context: Context): AppDatabase {
            return INSTANCE ?: synchronized(this) {
                INSTANCE ?: Room.databaseBuilder(
                    context.applicationContext,
                    AppDatabase::class.java,
                    "login.db"
                ).build().also { INSTANCE = it }
            }
        }
    }
}
  • @Database(entities = [Videojuego::class], version = 1) → declara qué entidades forman la base de datos.
  • exportSchema = false → no exporta el esquema a JSON.
  • Singleton → solo debe haber una instancia de AppDatabase en la app. El patrón INSTANCE ?: synchronized(...) lo garantiza.
  • @Volatile → asegura que INSTANCE se lea siempre de la memoria principal.

Paso 3: El repositorio

▾

7.1. ¿Por qué un repositorio?

Si HomeScreen accediera directamente a AppDatabase y a SessionDataStore, tendríamos:

  1. Acoplamiento: la UI sabría demasiado sobre la base de datos.
  2. Duplicación: si dos pantallas necesitan la lista, cada una crearía el DAO.
  3. Dificultad para testear.
  4. Complejidad: la UI tendría que saber que el email viene de DataStore y los videojuegos de Room.

El repositorio centraliza el acceso a los datos y expone una API simple a la UI.

import kotlinx.coroutines.flow.Flow

// ---------------------------------------------------------
// REPOSITORIO: capa intermedia entre la UI y las fuentes de datos.
//
// Une Room (videojuegos) y DataStore (sesión) en una sola API.
// La UI solo conoce esta clase; no sabe de Room ni de DataStore.
// ---------------------------------------------------------
class VideojuegoRepository(
    private val dao: VideojuegoDao,
    private val session: SessionDataStore
) {

    // ---------------------------------------------------------
    // VIDEOJUEGOS (vienen de Room)
    // ---------------------------------------------------------

    // Consulta reactiva: la UI se actualiza sola cuando cambia la tabla.
    val videojuegos: Flow<List<Videojuego>> = dao.getAll()

    // ---------------------------------------------------------
    // Operaciones de escritura.
    // Son `suspend` porque Room las ejecuta fuera del hilo principal.
    // ---------------------------------------------------------
    suspend fun insertar(videojuego: Videojuego) = dao.insert(videojuego)

    suspend fun actualizar(videojuego: Videojuego) = dao.update(videojuego)

    suspend fun borrar(videojuego: Videojuego) = dao.delete(videojuego)

    suspend fun borrarTodo() = dao.deleteAll()

    // ---------------------------------------------------------
    // SESIÓN (viene de DataStore)
    // ---------------------------------------------------------

    val emailUsuario: Flow<String> = session.emailFlow

    suspend fun guardarSesion(email: String, remember: Boolean) =
        session.saveSession(email, remember)

    suspend fun cerrarSesion() = session.clearSession()
}

  • class VideojuegoRepository(dao, session) → recibe el DAO y el SessionDataStore como dependencias. No los crea él; se los pasan desde fuera (inyección de dependencias manual).
  • val videojuegos: Flow<List<Videojuego>> → expone el Flow del DAO tal cual.
  • suspend fun insertar(...) → delega en el DAO.
  • val emailUsuario: Flow<String> → expone el Flow del email de DataStore.

VideojuegoViewModel.kt
package com.ejemplo.login

import androidx.lifecycle.ViewModel
import androidx.lifecycle.ViewModelProvider
import androidx.lifecycle.viewModelScope
import kotlinx.coroutines.flow.SharingStarted
import kotlinx.coroutines.flow.StateFlow
import kotlinx.coroutines.flow.stateIn
import kotlinx.coroutines.launch

// ---------------------------------------------------------
// VIEWMODEL: contiene la lógica de negocio de la pantalla Home.
//
// - Sobrevive a los cambios de configuración (rotaciones).
// - Expone el estado a la UI mediante StateFlow.
// - Recibe acciones de la UI (insertar, borrar, etc.).
// - Habla con el repositorio, no directamente con Room/DataStore.
// ---------------------------------------------------------
class VideojuegoViewModel(
    private val repository: VideojuegoRepository
) : ViewModel() {

    // ---------------------------------------------------------
    // ESTADO: lista de videojuegos como StateFlow.
    //
    // stateIn convierte el Flow del repositorio en un StateFlow:
    //   - viewModelScope: se cancela cuando el ViewModel se destruye.
    //   - SharingStarted.WhileSubscribed(5000): mantiene el Flow activo
    //     mientras haya suscriptores. Si no hay nadie durante 5 segundos,
    //     lo pausa (ahorra recursos).
    //   - emptyList(): valor inicial mientras llega el primer dato.
    // ---------------------------------------------------------
    val videojuegos: StateFlow<List<Videojuego>> = repository.videojuegos
        .stateIn(
            scope = viewModelScope,
            started = SharingStarted.WhileSubscribed(5_000),
            initialValue = emptyList()
        )

    // ---------------------------------------------------------
    // ESTADO: email del usuario como StateFlow.
    // ---------------------------------------------------------
    val emailUsuario: StateFlow<String> = repository.emailUsuario
        .stateIn(
            scope = viewModelScope,
            started = SharingStarted.WhileSubscribed(5_000),
            initialValue = ""
        )

    // ---------------------------------------------------------
    // ACCIONES: la UI llama a estas funciones.
    // Cada una lanza una corrutina en viewModelScope.
    // ---------------------------------------------------------

    fun insertar(videojuego: Videojuego) {
        viewModelScope.launch {
            repository.insertar(videojuego)
        }
    }

    fun actualizar(videojuego: Videojuego) {
        viewModelScope.launch {
            repository.actualizar(videojuego)
        }
    }

    fun borrar(videojuego: Videojuego) {
        viewModelScope.launch {
            repository.borrar(videojuego)
        }
    }

    fun borrarTodo() {
        viewModelScope.launch {
            repository.borrarTodo()
        }
    }

    fun cerrarSesion() {
        viewModelScope.launch {
            repository.cerrarSesion()
        }
    }
}

// ---------------------------------------------------------
// FACTORY: le dice a Compose cómo construir el ViewModel.
//
// El ViewModel necesita un repositorio, que no puede crear solo.
// La factory se lo pasa.
// ---------------------------------------------------------
class VideojuegoViewModelFactory(
    private val repository: VideojuegoRepository
) : ViewModelProvider.Factory {

    @Suppress("UNCHECKED_CAST")
    override fun <T : ViewModel> create(modelClass: Class<T>): T {
        if (modelClass.isAssignableFrom(VideojuegoViewModel::class.java)) {
            return VideojuegoViewModel(repository) as T
        }
        throw IllegalArgumentException("ViewModel desconocido: ${modelClass.name}")
    }
}

Puntos clave:

  • viewModelScope → scope de corrutinas que se cancela con el ViewModel.
  • stateIn(...) → convierte un Flow en StateFlow: scope = viewModelScope (vive mientras viva el ViewModel), started = SharingStarted.WhileSubscribed(5_000) (mantiene el Flow activo mientras haya suscriptores) e initialValue = emptyList() (valor inicial).
  • VideojuegoViewModelFactory → construye el ViewModel con el repositorio inyectado.

10.3. Crear NotificationHelper.kt

Archivo nuevo: app/src/main/java/com/ejemplo/login/NotificationHelper.kt

NotificationHelper.kt
package com.ejemplo.login

import android.app.NotificationChannel
import android.app.NotificationManager
import android.content.Context
import android.os.Build
import androidx.core.app.NotificationCompat
import androidx.core.app.NotificationManagerCompat

// ---------------------------------------------------------
// Helper para gestionar notificaciones.
//
// - Crea el canal (obligatorio desde Android 8).
// - Muestra notificaciones.
// ---------------------------------------------------------
object NotificationHelper {

    private const val CHANNEL_ID = "login_videojuegos"
    private const val CHANNEL_NAME = "Videojuegos"
    private const val CHANNEL_DESC = "Notificaciones al añadir videojuegos"

    // ---------------------------------------------------------
    // Crea el canal. Es idempotente: si ya existe, no hace nada.
    // Se llama al arrancar la app (por ejemplo, en MainActivity).
    // ---------------------------------------------------------
    fun createChannel(context: Context) {
        if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.O) {
            val channel = NotificationChannel(
                CHANNEL_ID,
                CHANNEL_NAME,
                NotificationManager.IMPORTANCE_DEFAULT
            ).apply {
                description = CHANNEL_DESC
            }
            val manager = context.getSystemService(NotificationManager::class.java)
            manager.createNotificationChannel(channel)
        }
    }

    // ---------------------------------------------------------
    // Muestra una notificación.
    // Antes de llamar a esta función, hay que comprobar que
    // el permiso POST_NOTIFICATIONS está concedido.
    // ---------------------------------------------------------
    fun mostrarNotificacion(
        context: Context,
        titulo: String,
        mensaje: String
    ) {
        val notification = NotificationCompat.Builder(context, CHANNEL_ID)
            .setSmallIcon(android.R.drawable.ic_dialog_info)
            .setContentTitle(titulo)
            .setContentText(mensaje)
            .setPriority(NotificationCompat.PRIORITY_DEFAULT)
            .setAutoCancel(true)
            .build()

        try {
            NotificationManagerCompat.from(context).notify(
                System.currentTimeMillis().toInt(),
                notification
            )
        } catch (e: SecurityException) {
            // El permiso no está concedido. No hacemos nada.
        }
    }
}
  • NotificationChannel → obligatorio desde Android 8.
  • Build.VERSION.SDK_INT >= Build.VERSION_CODES.O → el canal solo existe desde API 26.
  • NotificationCompat.Builder → compatible con todas las versiones.
  • try/catch (SecurityException) → si el permiso no está concedido, no se cierra la app.

Requisitos y preparación del entorno

Antes de instalar nada, comprueba que tu equipo aguanta el IDE y el emulador con soltura.

Almacenamiento libre8 GB20 GB o más
Pantalla1280 x 8001920 x 1080 o superior

Versión de Android Studio recomendada

  • Usar la versión estable más reciente disponible en la web oficial de Android Developers.
  • En el momento de redactar esta guía, la versión estable es Android Studio Quail 4 (2026.1.4).
  • Si el centro ya tiene instalada una versión anterior (por ejemplo, Otter 2), se puede instalar Quail 4 en paralelo sin sobrescribirla.
Nota: las versiones «Canary» o «Preview» pueden tener errores. Para clase, siempre que sea posible, usa la versión estable.

Instalación en paralelo (convivencia de dos versiones)

Para tener dos versiones de Android Studio en el mismo equipo:

  1. Descargar el paquete .zip (no el .exe) desde la página de Preview o desde el Archivo de descargas de Android Studio.
  2. Descomprimir el .zip en una carpeta separada, por ejemplo: C:\Android\Quail4\.
  3. Entrar en la subcarpeta bin y crear un acceso directo a studio64.exe.
  4. Renombrar el acceso directo para diferenciarlo (por ejemplo, «Android Studio Quail 4»).
Notas importantes:
  • El paquete .zip no se instala: no escribe en el registro de Windows ni crea entradas de menú. Es portable, aunque guarda su configuración en el perfil del usuario (%LOCALAPPDATA%\Google\AndroidStudio<versión>).
  • Cada versión usa su propia carpeta de configuración, por lo que no se pisan las preferencias.
  • Ambas versiones comparten el mismo Android SDK por defecto.

Archivos studio64.exe y studio.bat

ArchivoPara qué sirve
studio64.exeEjecutable normal. Se usa siempre (a través del acceso directo).
studio.batScript de arranque que busca el JDK y configura el entorno antes de lanzar el IDE. Se usa solo para diagnóstico si el IDE no arranca: ejecutarlo desde una terminal muestra los errores en pantalla.

Dónde se guardan los proyectos

Por defecto, Android Studio guarda los proyectos en:

C:\Users\<tu-usuario>\AndroidStudioProjects

Puedes cambiarlo al crear cada proyecto.

03

Instalación de Android Studio

Instalación estándar (versión única)

  1. Descargar el instalador desde la web oficial de Android Developers.
  2. Ejecutar el .exe y aceptar los avisos de control de cuentas de usuario (UAC).
  3. Seguir el asistente aceptando las opciones por defecto.
  4. Al abrir por primera vez, elegir tema (claro u oscuro).
  5. En el Setup Wizard, seleccionar la opción Standard para que se descarguen e instalen automáticamente los componentes esenciales (Android SDK, herramientas de compilación, etc.).
  6. Permitir los permisos de Windows que solicite (por ejemplo, para adb.exe).

Cambiar el idioma de la interfaz a español

Si prefieres la interfaz en español:

  1. Ir a Settings > Appearance & Behavior > System Settings > Language.
  2. Seleccionar Español.
  3. Reiniciar Android Studio.
Consejo: aunque la interfaz esté en español, muchos mensajes de error de Gradle seguirán en inglés. Es bueno acostumbrarse a ambos.

Configuración inicial y antivirus

Exclusión de Windows Defender

Los cierres repentinos de Android Studio suelen deberse al escaneo en tiempo real de Windows Defender. Se recomienda añadir estas carpetas a las exclusiones de Seguridad de Windows:

CarpetaRuta típica
Caché de Gradle%USERPROFILE%\.gradle
Proyectos%USERPROFILE%\AndroidStudioProjects
SDK de Android%USERPROFILE%\AppData\Local\Android\Sdk
Configuración del IDE%LOCALAPPDATA%\Google\AndroidStudio<versión>

Cómo añadirlas:

  1. Abrir Seguridad de Windows.
  2. Ir a Protección frente a virus y amenazas > Administrar la configuración > Exclusiones.
  3. Añadir cada carpeta.
Aviso: si hay otro antivirus instalado (Kaspersky, ESET, etc.), aplica las mismas exclusiones en él. Una actualización de Windows puede borrar las exclusiones: revísalas de vez en cuando.

Configuración del JDK

Android Studio incluye su propio JDK (JetBrains Runtime). Normalmente no necesitas configurar nada.

Si tienes problemas de compilación por incompatibilidad de versiones:

  1. Ir a Settings > Build, Execution, Deployment > Build Tools > Gradle.
  2. En Gradle JDK, seleccionar una versión compatible (por ejemplo, 17).
  3. Pulsar Apply y OK.
  4. Hacer File > Sync Project with Gradle Files.

Gestión del SDK

Desde Tools > SDK Manager puedes:

  • Ver qué versiones del SDK de Android tienes instaladas.
  • Instalar nuevas plataformas (por ejemplo, Android 15).
  • Instalar herramientas de compilación adicionales.
  • Actualizar componentes existentes.
05

Creación de un proyecto nuevo

Pasos

  1. En la pantalla de bienvenida, pulsar «New Project».
  2. Elegir la plantilla «Empty Activity» (pestaña «Phone and Tablet»).
  3. Configurar:
    • Name: nombre de la app (por ejemplo, MiPrimerAplicacion).
    • Package name: se genera automáticamente (com.example.miprimeraaplicacion).
    • Minimum SDK: se recomienda API 24 (Android 7.0 Nougat) para máxima compatibilidad.
  4. Pulsar «Finish» y esperar a que Gradle configure el proyecto.
Nota: la primera vez que se crea un proyecto, Android Studio descarga muchas dependencias. Puede tardar varios minutos. Verás una barra de progreso en la parte inferior.

Qué ocurre internamente al crear el proyecto

  1. Android Studio genera la estructura de carpetas.
  2. Crea los archivos build.gradle.kts con las dependencias básicas.
  3. Descarga el Gradle Wrapper correspondiente.
  4. Descarga las dependencias de AndroidX, Compose, etc.
  5. Indexa todos los archivos (verás «Indexing...» en la parte inferior).

Sobre el Gradle Wrapper

  • Android Studio no usa una instalación externa de Gradle, sino el Gradle Wrapper del proyecto.
  • El wrapper se define en gradle/wrapper/gradle-wrapper.properties (indica la versión) y se ejecuta con gradlew / gradlew.bat.
  • Cada proyecto tiene su propio wrapper, por lo que puede usar una versión distinta de Gradle.
  • Al cambiar de versión, el wrapper descarga automáticamente los binarios necesarios la primera vez.
06

El emulador (AVD) y cómo ejecutar la app

¿Qué es un AVD?

Un AVD (Android Virtual Device) es un emulador de teléfono Android que se ejecuta en tu ordenador. Te permite probar apps sin necesidad de un móvil físico.

Crear un AVD

  1. Ir a Tools > Device Manager.
  2. Pulsar «+» (Create Virtual Device).
  3. Elegir un modelo (por ejemplo, Pixel 6).
  4. Seleccionar una imagen del sistema (por ejemplo, Android 14 / UpsideDownCake). Si no está descargada, pulsar el icono de descarga y aceptar los términos.
  5. Ponerle un nombre al AVD (por ejemplo, Pixel_Clase) y finalizar.

Ejecutar la app: flujo completo

  1. Seleccionar dispositivo: en la barra superior, en el desplegable de dispositivo, elegir el AVD que acabas de crear.
  2. Pulsar Run (▶️) o usar Shift+F10.
  3. Esperar la compilación: verás el progreso en el panel Build (abajo). La primera vez tarda más.
  4. Arranque del emulador: si no estaba abierto, se abrirá automáticamente. Puede tardar 1-2 minutos.
  5. Instalación y ejecución: Android Studio instala la app en el emulador y la abre.
  6. Resultado: verás tu app en pantalla.
Consejo: no cierres el emulador entre ejecuciones. Dejarlo abierto en segundo plano acelera mucho las siguientes compilaciones.

Si algo falla

  • BUILD FAILED: mira el panel Build para ver el error real.
  • El emulador no arranca: revisa que la virtualización esté activada en la BIOS/UEFI.
  • La app se cierra al abrirse: mira el panel Logcat para ver el error.

Raíz del proyecto. Contiene el módulo app y los scripts de configuración compartidos. Módulo de la aplicación: aquí vive todo el código y los recursos de tu app. Código y recursos principales de la app final (lo que se compila en el APK). A pesar del nombre, contiene archivos .kt de Kotlin: MainActivity.kt (actividad principal) y ui/theme/ (tema visual). Actividad principal de la app. Punto de entrada de la interfaz Compose — la vemos en detalle en la siguiente sección. Contiene Color.kt (colores), Theme.kt (tema claro/oscuro) y Type.kt (tipografía). El «DNI» de la app: declara paquete, permisos, actividades y el punto de entrada. La vemos en detalle más abajo. Tests unitarios que se ejecutan en la JVM (sin dispositivo ni emulador). Tests instrumentados: se ejecutan en un dispositivo o emulador real. Configuración del módulo app: compileSdk, minSdk, targetSdk, applicationId y el bloque dependencies. Reglas de ofuscación y reducción de código para compilaciones de release. Versión de Gradle y .jar del wrapper — permite que el proyecto use Gradle sin instalarlo. Configuración global: plugins y ajustes comunes a todos los módulos del proyecto. Declara los módulos del proyecto (normalmente solo :app). Propiedades de Gradle: memoria asignada, flags de compilación, etc. Scripts para ejecutar Gradle sin necesidad de instalarlo en el sistema.

El código de MainActivity.kt, el Manifest y los recursos

Código completo

package com.example.miprimeraplicacion

import android.os.Bundle
import androidx.activity.ComponentActivity
import androidx.activity.compose.setContent
import androidx.activity.enableEdgeToEdge
import androidx.compose.foundation.layout.fillMaxSize
import androidx.compose.foundation.layout.padding
import androidx.compose.material3.Scaffold
import androidx.compose.material3.Text
import androidx.compose.runtime.Composable
import androidx.compose.ui.Modifier
import androidx.compose.ui.tooling.preview.Preview
import com.example.miprimeraplicacion.ui.theme.MiPrimerAplicacionTheme

class MainActivity : ComponentActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        enableEdgeToEdge()
        setContent {
            MiPrimerAplicacionTheme {
                Scaffold(modifier = Modifier.fillMaxSize()) { innerPadding ->
                    Greeting(
                        name = "Android",
                        modifier = Modifier.padding(innerPadding)
                    )
                }
            }
        }
    }
}

@Composable
fun Greeting(name: String, modifier: Modifier = Modifier) {
    Text(
        text = "Hello $name!",
        modifier = modifier
    )
}

@Preview(showBackground = true)
@Composable
fun GreetingPreview() {
    MiPrimerAplicacionTheme {
        Greeting("Android")
    }
}

Explicación por bloques

  • package: identifica el archivo dentro del proyecto. Coincide con la ruta de carpetas.
  • import: trae clases y funciones de otras librerías. Los que empiezan por androidx.compose son de Jetpack Compose.
  • Hereda de ComponentActivity, versión moderna pensada para Compose.
  • onCreate: método que se ejecuta al crear la Activity. Es el punto de entrada.
  • super.onCreate(...): inicializa la clase padre.
  • enableEdgeToEdge(): hace que la app ocupe toda la pantalla, incluso detrás de las barras del sistema.
  • setContent { ... }: conecta Compose con la Activity. Todo lo que va dentro es interfaz declarativa.
  • MiPrimerAplicacionTheme: aplica colores, tipografía y formas definidos en ui/theme/.
  • Componente de Material 3 que proporciona la estructura básica de pantalla (barra superior, inferior, etc.).
  • Modifier.fillMaxSize(): ocupa toda la pantalla.
  • innerPadding: padding interno calculado por el Scaffold para que el contenido no quede tapado por las barras del sistema.
  • @Composable: marca la función como parte de la interfaz. Solo las funciones así pueden llamar a otros composables.
  • Recibe name (String) y modifier (Modifier, por defecto vacío).
  • Text(...): composable que muestra texto. Equivale a un TextView clásico.
  • "Hello $name!": interpolación de strings. $name se sustituye por el valor de la variable.
¿Por qué se pasa modifier como parámetro? Es una convención de Compose: cada composable acepta un Modifier para que quien lo use pueda aplicar padding, tamaño, etc. desde fuera. Esto hace los composables reutilizables.
  • @Preview: le dice a Android Studio que muestre esta función en el panel de vista previa. No se ejecuta en la app, solo en el IDE.
  • showBackground = true: muestra un fondo blanco detrás de la previsualización.
  • Envuelve Greeting("Android") en el tema para que use los mismos colores y tipografía que la app real.

Flujo de ejecución

MainActivity.onCreate()
    → setContent { ... }           ← conecta Compose con la Activity
        → MiPrimerAplicacionTheme  ← aplica colores y tipografía
            → Scaffold             ← estructura de pantalla + padding
                → Greeting()       ← el contenido visible
                    → Text()       ← el texto en pantalla

En paralelo, GreetingPreview permite ver Greeting en el panel Design o Split del editor, sin ejecutar la app.

Conceptos mínimos para empezar:
  1. onCreate es el punto de entrada de la Activity.
  2. setContent es donde se describe la interfaz.
  3. Greeting es una función que dibuja algo en pantalla.
  4. @Composable marca las funciones que forman parte de la interfaz.
  5. @Preview sirve para ver el resultado sin ejecutar.

AndroidManifest.xml y su relación con MainActivity

Es el «DNI» de la aplicación. Declara el paquete de la app, los permisos que necesita, las actividades que contiene, el punto de entrada y la versión/SDK mínimo-objetivo.

<?xml version="1.0" encoding="utf-8"?>
<manifest xmlns:android="http://schemas.android.com/apk/res/android">

    <application
        android:allowBackup="true"
        android:icon="@mipmap/ic_launcher"
        android:label="@string/app_name"
        android:theme="@style/Theme.MiPrimerAplicacion">

        <activity
            android:name=".MainActivity"
            android:exported="true"
            android:theme="@style/Theme.MiPrimerAplicacion">
            <intent-filter>
                <action android:name="android.intent.action.MAIN" />
                <category android:name="android.intent.category.LAUNCHER" />
            </intent-filter>
        </activity>

    </application>

</manifest>
  • La etiqueta <activity android:name=".MainActivity"> declara que existe una Activity llamada MainActivity.
  • El <intent-filter> con MAIN y LAUNCHER indica que esa Activity es el punto de entrada de la app: es la que se abre al pulsar el icono.
  • Si creas una segunda Activity, tienes que registrarla aquí también.

Recursos: strings.xml y buenas prácticas

Es un archivo en res/values/ donde se definen todos los textos de la app.

<resources>
    <string name="app_name">Mi Primera Aplicación</string>
    <string name="saludo">¡Hola desde mi app!</string>
</resources>

¿Por qué usarlo en lugar de hardcodear textos?

  • Internacionalización: puedes crear values-en/strings.xml, values-fr/strings.xml, etc. para traducir la app.
  • Mantenimiento: si cambias un texto, lo cambias en un solo sitio.
  • Buenas prácticas: es el estándar de Android.

Cómo usarlo en Compose:

Text(text = stringResource(id = R.string.saludo))
Nota: para apps de aprendizaje, hardcodear textos es aceptable al principio. Pero es bueno acostumbrarse a strings.xml desde el principio.

Depuración básica: Logcat y Debug

Logcat

Logcat muestra los mensajes que emite la app mientras se ejecuta. Es tu mejor amigo cuando algo falla.

  • Niveles de log: Verbose, Debug, Info, Warn, Error.
  • Filtros: puedes filtrar por nivel, por tag o por texto.
  • Uso típico: si la app se cierra inesperadamente, busca FATAL EXCEPTION en Logcat.
Prueba el simulador de Logcat de la cabecera de la guía: cambia el escenario a «💥 La app se cierra» y filtra por FATAL para ver justo lo que describe este apartado.

Cómo escribir un log desde el código

import android.util.Log

Log.d("MiTag", "Mensaje de depuración")
Log.e("MiTag", "Mensaje de error")

Debug con puntos de ruptura

  1. Haz clic en el margen izquierdo del editor, junto a la línea donde quieras parar. Aparecerá un punto rojo.
  2. Pulsa 🐞 Debug (Shift+F9).
  3. La app se ejecutará y se detendrá en esa línea.
  4. En el panel Debugger puedes:
    • Ver el valor de las variables.
    • Avanzar paso a paso (F8).
    • Entrar en una función (F7).
    • Continuar (F9).

Problemas frecuentes y soluciones

Antes de pedir ayuda, comprueba si tu problema está aquí. Piensa primero en la causa antes de revelar la solución.

⚠

Advertencia «Unable to strip the following libraries»

Unable to strip the following libraries, packaging them as they are:
libandroidx.graphics.path.so.
Es solo una advertencia, no un error. La biblioteca ya viene sin símbolos de depuración, así que Gradle no puede «strippearla» y la empaqueta tal cual. No requiere acción: se puede ignorar con seguridad.
⚠

Error de compilación por incompatibilidad de Gradle

Síntoma: la compilación falla con Execution failed for task ':app:compileDebugKotlin' y/o un aviso de que Gradle ya está en una versión más nueva.

Causa: el proyecto usa una versión de Gradle que no es compatible con la versión del Android Gradle Plugin (AGP). Por ejemplo, AGP 8.x no es compatible con Gradle 9.6+.

Solución:

  1. Aceptar el enlace de actualización que ofrece Android Studio. Esto reescribe gradle/wrapper/gradle-wrapper.properties con la nueva versión.
  2. Pulsar Sync para que Gradle descargue los binarios necesarios (.jar, .pom, .module).
  3. Volver a compilar.

Alternativa: ajustar el JDK del IDE en Settings > Build, Execution, Deployment > Build Tools > Gradle > Gradle JDK a una versión compatible (por ejemplo, 17).

📋

Cómo leer un error de Gradle

Los errores de Gradle son larguísimos. Para encontrar el problema real:

  1. Abre el panel Build (abajo).
  2. Busca la línea que empieza por FAILURE.
  3. Justo debajo, busca What went wrong.
  4. Ahí está la descripción del error real.
💥

Cierres repentinos del IDE

Causa más probable: Windows Defender escaneando en tiempo real las carpetas de trabajo.

Solución: añade las exclusiones indicadas en el apartado de configuración inicial. Reinicia el equipo para limpiar bloqueos huérfanos.

📱

El emulador no arranca

  • Revisa que la virtualización esté activada en la BIOS/UEFI.
  • En Windows 11, comprueba que Hyper-V o Windows Hypervisor Platform estén activados.
  • Prueba a crear un AVD con una imagen del sistema más ligera.
🔄

Gradle se queda colgado en «Sync»

  • Comprueba la conexión a internet (Gradle descarga dependencias).
  • Prueba File > Invalidate Caches / Restart.
  • Si persiste, borra la carpeta .gradle del proyecto y vuelve a sincronizar.
⏳

«Indexing» tarda mucho

Es normal la primera vez. Android Studio está indexando todos los archivos del proyecto y las dependencias. En proyectos grandes puede tardar varios minutos.

Control de versiones con Git y siguientes pasos

Inicializar Git en el proyecto

Android Studio detecta automáticamente si el proyecto no está bajo control de versiones. Puedes:

  • Ir a VCS > Enable Version Control Integration y elegir Git.
  • O hacerlo desde terminal:
git init
git add .
git commit -m "Primer commit"

Archivos que NO debes subir

Android Studio genera un archivo .gitignore por defecto que excluye:

  • .gradle/ → caché de Gradle.
  • build/ → artefactos de compilación.
  • local.properties → rutas locales del SDK.
  • .idea/ → configuración del IDE.
Nota: no borres el .gitignore. Es tu amigo.

Conectar con GitHub

  1. File > Settings > Version Control > GitHub → añadir tu cuenta.
  2. Git > GitHub > Share Project on GitHub.
  3. Elegir nombre y visibilidad del repositorio.

Siguientes pasos

Una vez dominado lo básico, estos son los siguientes pasos naturales:

Añadir interactividad

  • Un Button que al pulsarlo cambie un texto.
  • Estado con remember { mutableStateOf(...) }.

Organizar la interfaz

  • Column, Row y Box para organizar elementos.
  • Modifier para padding, tamaño, alineación.

Navegar entre pantallas

  • Añadir una segunda pantalla.
  • Navigation Compose para navegar entre ellas.

Persistir datos

  • SharedPreferences o DataStore.
  • Bases de datos con Room.

Consumir APIs

  • Peticiones HTTP con Retrofit o Ktor.
  • Parsear JSON con Kotlin Serialization.

Recursos recomendados

  • developer.android.com
  • Codelabs de Android
  • Kotlin Playground
  • Curso «Android Basics with Compose» (Google)

Glosario y preguntas frecuentes

Glosario

Activity
Pantalla de la aplicación. Es el componente básico de la UI en Android.
AGP
Android Gradle Plugin. Plugin que integra Gradle con Android.
AVD
Android Virtual Device. Emulador de teléfono Android.
Composable
Función marcada con @Composable que forma parte de la interfaz en Compose.
Compose
Jetpack Compose. Sistema de interfaz moderno de Android.
Gradle
Sistema de construcción y gestión de dependencias.
Gradle Wrapper
Mecanismo que permite usar Gradle sin instalarlo, descargando la versión que el proyecto necesita.
JDK
Java Development Kit. Entorno de desarrollo para Java, necesario para ejecutar Gradle y Kotlin.
Logcat
Visor de logs del dispositivo o emulador.
Modifier
Objeto de Compose que permite aplicar modificaciones a un composable (padding, tamaño, etc.).
Package name
Identificador único de la app (por ejemplo, com.example.miapp).
Scaffold
Componente de Material 3 que proporciona la estructura básica de una pantalla.
SDK
Software Development Kit. Conjunto de herramientas para desarrollar en una plataforma.
Target SDK
Versión de Android para la que está optimizada la app.

Ningún término coincide con esa búsqueda.

01

Introducción

Esta guía práctica te llevará a desplegar un stack LAMP completo usando Docker: un servidor web Apache, un contenedor PHP-FPM que ejecuta código PHP, y una base de datos MariaDB. Todo ello orquestado con Docker Compose.

LAMP son las siglas de Linux + Apache + MySQL/MariaDB + PHP. Es el stack clásico para aplicaciones web en PHP. Usaremos MariaDB (compatible con MySQL y de código abierto).

Se trabajan los conceptos desarrollados en la Unidad de Trabajo 1. Si algo no te suena (qué es un volumen, qué diferencia hay entre imagen y contenedor, qué es FastCGI), consulta la guía teórica de la unidad antes de continuar.

El objetivo es que, al terminar, no solo tengas el stack funcionando sino que también entiendas cómo se comunican los contenedores entre sí (Apache ↔ PHP-FPM ↔ MariaDB), cómo persiste la base de datos y cómo verificar que todo funciona correctamente.

02

Objetivos de aprendizaje

  • Preparar un entorno de trabajo con Docker en Windows 11.
  • Definir un stack multi-contenedor con Docker Compose.
  • Crear un Dockerfile personalizado para PHP-FPM con las extensiones necesarias.
  • Configurar Apache como servidor web delegando PHP a PHP-FPM via FastCGI.
  • Desplegar MariaDB con persistencia de datos mediante volúmenes.
  • Verificar el correcto funcionamiento de cada componente.
  • Diagnosticar y resolver problemas frecuentes (Error 500, conexión BD, etc.).
03

Prerrequisitos

Antes de empezar, asegúrate de que tienes:

  • Windows 11 con Docker Desktop instalado y funcionando.
  • Una terminal (PowerShell o Windows Terminal).
  • Un editor de texto (VS Code, Notepad++...).

Verificación rápida de Docker

powershell
docker --version
docker compose version

Ambos comandos deben devolver una versión. Si alguno falla, revisa la instalación de Docker antes de continuar.

Preparación del sistema operativo del servidor

Paso 1 · Crear la estructura de carpetas

Vamos a crear la estructura de carpetas del proyecto:

powershell
mkdir lamp-docker\apache
mkdir lamp-docker\php
mkdir lamp-docker\mariadb
mkdir lamp-docker\src
cd lamp-docker
árbol de directorios
lamp-docker/
├── docker-compose.yml
├── apache/
│   ├── Dockerfile
│   └── vhost.conf
├── php/
│   └── Dockerfile
├── mariadb/
│   └── init.sql
└── src/
    └── index.php
Consejo

Evita rutas con espacios o caracteres especiales. Docker y algunos comandos pueden dar problemas.

Paso 2 · Verificar recursos asignados a Docker

Docker Desktop permite limitar la CPU, RAM y disco que puede usar el motor de Docker. Para esta práctica, con 2 GB de RAM y 2 CPU es suficiente. Puedes comprobarlo en Docker Desktop → Settings → Resources.

Paso 3 · Verificar que los puertos están libres

Vamos a usar los puertos 8080 (Apache) y 3306 (MariaDB).

powershell
netstat -ano | findstr :8080
netstat -ano | findstr :3306

Si no devuelven nada, están libres. Si devuelven algo, cambia el puerto en el docker-compose.yml más adelante.

05

Arquitectura del stack a desplegar

En esta práctica desplegaremos la siguiente arquitectura de 3 contenedores:

  • Apache recibe las peticiones HTTP en el puerto 8080 y sirve archivos estáticos.
  • PHP-FPM ejecuta el código PHP, conectado a Apache por el protocolo FastCGI.
  • MariaDB almacena los datos de la aplicación. PHP se conecta via PDO o mysqli.
  • Volumen mariadb_data persiste los datos de la base de datos entre arranques.
  • Los tres contenedores comparten la red lamp-network, lo que permite que se resuelvan por nombre de servicio.
06

Creación del stack paso a paso con Docker Compose

Paso 1 · Crear el Dockerfile de PHP y Apache

Crea el archivo php/Dockerfile para PHP-FPM:

dockerfile
FROM php:8.2-fpm-alpine

# Instalar las extensiones PHP necesarias
RUN docker-php-ext-install \
    pdo \
    pdo_mysql \
    mysqli

WORKDIR /var/www/html

Crea el archivo apache/Dockerfile para Apache (con los módulos de proxy pre-cargados):

apache/Dockerfile
FROM httpd:2.4-alpine

# Habilitar módulos de proxy para FastCGI
RUN sed -i '/^#LoadModule proxy_module/s/^#//' conf/httpd.conf \
    && sed -i '/^#LoadModule proxy_fcgi_module/s/^#//' conf/httpd.conf \
    && sed -i '/^#LoadModule socache_shmcb_module/s/^#//' conf/httpd.conf
Explicación

Por defecto, la imagen httpd:2.4-alpine tiene los módulos mod_proxy y mod_proxy_fcgi comentados. Este Dockerfile los activa.

dockerfile
FROM php:8.2-fpm-alpine

# Instalar las extensiones PHP necesarias
RUN docker-php-ext-install \
    pdo \
    pdo_mysql \
    mysqli

WORKDIR /var/www/html
Explicación

FROM php:8.2-fpm-alpine parte de la imagen oficial de PHP 8.2 con FPM (FastCGI Process Manager), en su versión Alpine (ligera). docker-php-ext-install pdo pdo_mysql mysqli instala las extensiones para conectar con MariaDB. WORKDIR /var/www/html establece el directorio de trabajo dentro del contenedor.

Paso 2 · Configurar Apache (VirtualHost)

Crea el archivo apache/vhost.conf. Apache delegará los archivos .php a PHP-FPM via FastCGI:

apache
<VirtualHost *:80>
    ServerName localhost
    DocumentRoot /var/www/html

    <Directory /var/www/html>
        Options Indexes FollowSymLinks
        AllowOverride All
        Require all granted
        DirectoryIndex index.php index.html
    </Directory>

    # Delegar los archivos .php a PHP-FPM
    <FilesMatch \.php$>
        SetHandler "proxy:fcgi://php-fpm:9000"
    </FilesMatch>

    ErrorLog /proc/self/fd/2
    CustomLog /proc/self/fd/1 combined
</VirtualHost>
Puntos clave

SetHandler "proxy:fcgi://php-fpm:9000" delega todos los archivos .php al contenedor llamado php-fpm en el puerto 9000. El nombre php-fpm debe coincidir con el nombre del servicio en docker-compose.yml.

Paso 3 · Configurar MariaDB (init.sql)

Crea el archivo mariadb/init.sql. Este script se ejecuta automáticamente la primera vez que arranque MariaDB:

sql
-- Crear una tabla de prueba
CREATE TABLE IF NOT EXISTS test_table (
    id INT AUTO_INCREMENT PRIMARY KEY,
    mensaje VARCHAR(255) NOT NULL,
    fecha TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Insertar un par de filas
INSERT INTO test_table (mensaje) VALUES
    ('Hola desde MariaDB'),
    ('¡LAMP funcionando en Docker!');
Nota

Este script solo se ejecuta la primera vez que se crea el volumen de datos de MariaDB. Si más adelante modificas este archivo y quieres que se vuelva a ejecutar, tienes que borrar el volumen con docker compose down -v.

Paso 4 · Crear docker-compose.yml

yaml
services:
  # ---- Apache ----
  apache:
    build: ./apache
    container_name: lamp-apache
    ports:
      - "8080:80"
    volumes:
      - ./src:/var/www/html
      - ./apache/vhost.conf:/usr/local/apache2/conf/extra/vhost.conf:ro
    command: >
      sh -c "echo 'Include conf/extra/vhost.conf' >> conf/httpd.conf && httpd-foreground"
    networks:
      - lamp-network
    depends_on:
      - php-fpm
    restart: unless-stopped

  # ---- PHP-FPM ----
  php-fpm:
    build: ./php
    container_name: lamp-php
    volumes:
      - ./src:/var/www/html
    networks:
      - lamp-network
    depends_on:
      mariadb:
        condition: service_healthy
    restart: unless-stopped

  # ---- MariaDB ----
  mariadb:
    image: mariadb:11
    container_name: lamp-mariadb
    environment:
      MARIADB_ROOT_PASSWORD: rootpass
      MARIADB_DATABASE: lamp_db
      MARIADB_USER: lamp_user
      MARIADB_PASSWORD: lamp_pass
    volumes:
      - mariadb_data:/var/lib/mysql
      - ./mariadb/init.sql:/docker-entrypoint-initdb.d/init.sql:ro
    ports:
      - "3306:3306"
    networks:
      - lamp-network
    healthcheck:
      test: ["CMD", "healthcheck.sh", "--connect", "--innodb_initialized"]
      interval: 5s
      timeout: 5s
      retries: 10
    restart: unless-stopped

networks:
  lamp-network:
    driver: bridge

volumes:
  mariadb_data:

Paso 5 · Crear index.php de prueba

Crea el archivo src/index.php. Esta página verificará que PHP funciona y se conecta a MariaDB:

php
<!DOCTYPE html>
<html lang="es">
<head>
    <meta charset="UTF-8">
    <title>Prueba LAMP en Docker</title>
    <style>
        body { font-family: Arial, sans-serif; max-width: 800px; margin: 40px auto; padding: 20px; }
        h1 { color: #333; }
        .ok { color: green; font-weight: bold; }
        .error { color: red; font-weight: bold; }
        table { border-collapse: collapse; margin-top: 20px; width: 100%; }
        th, td { border: 1px solid #ccc; padding: 8px; text-align: left; }
        th { background-color: #f4f4f4; }
    </style>
</head>
<body>
    <h1>Prueba funcional del stack LAMP</h1>

    <h2>1. Comprobación de PHP</h2>
    <?php
    echo "<p class='ok'>PHP funciona correctamente. Versión: " . phpversion() . "</p>";
    ?>

    <h2>2. Conexión a MariaDB</h2>
    <?php
    $host = 'mariadb';
    $db   = 'lamp_db';
    $user = 'lamp_user';
    $pass = 'lamp_pass';

    try {
        $pdo = new PDO("mysql:host=$host;dbname=$db;charset=utf8mb4", $user, $pass);
        $pdo->setAttribute(PDO::ATTR_ERRMODE, PDO::ERRMODE_EXCEPTION);
        echo "<p class='ok'>Conexión a MariaDB establecida correctamente.</p>";

        $stmt = $pdo->query("SELECT id, mensaje, fecha FROM test_table ORDER BY id");
        $filas = $stmt->fetchAll(PDO::FETCH_ASSOC);

        if (count($filas) > 0) {
            echo "<h2>3. Datos leídos de la base de datos</h2>";
            echo "<table>";
            echo "<tr><th>ID</th><th>Mensaje</th><th>Fecha</th></tr>";
            foreach ($filas as $fila) {
                echo "<tr>";
                echo "<td>" . htmlspecialchars($fila['id']) . "</td>";
                echo "<td>" . htmlspecialchars($fila['mensaje']) . "</td>";
                echo "<td>" . htmlspecialchars($fila['fecha']) . "</td>";
                echo "</tr>";
            }
            echo "</table>";
        } else {
            echo "<p>La tabla existe pero está vacía.</p>";
        }
    } catch (PDOException $e) {
        echo "<p class='error'>Error de conexión: " . htmlspecialchars($e->getMessage()) . "</p>";
    }
    ?>

    <h2>4. Información del entorno</h2>
    <p>Si ves esta página, Apache y PHP-FPM están trabajando juntos correctamente.</p>
</body>
</html>

Paso 6 · Levantar y verificar

powershell · levantar
docker compose up -d --build

La primera ejecución puede tardar unos minutos porque descarga las imágenes de Apache, PHP y MariaDB.

powershell · verificar
docker compose ps

Deberías ver los tres contenedores en estado Up.

powershell · verificar (opcional)
docker compose exec php-fpm php -v
docker compose exec php-fpm php -m | findstr pdo
07

Comprobación del sistema

Paso 1 · Abrir en el navegador

Abre tu navegador y accede a:

url
http://localhost:8080

Deberías ver:

  • Comprobación de PHP: la versión de PHP que está corriendo.
  • Conexión a MariaDB: mensaje en verde confirmando la conexión.
  • Tabla con datos: las dos filas que insertamos en init.sql.

Si todo aparece correctamente, tu LAMP está funcionando.

Pasos adicionales de verificación

powershell
docker compose logs apache
docker compose logs php-fpm
docker compose logs mariadb
Consejo

Si algo no funciona, los logs suelen contener la pista. Busca líneas con error, failed o warning.

powershell
docker exec -it lamp-php sh
sh
hostname -i          # IP del contenedor
ping mariadb         # Resolución por nombre
exit                 # Salir
powershell
docker exec -it lamp-mariadb mariadb -u lamp_user -p

Contraseña: lamp_pass. Dentro puedes ejecutar USE lamp_db; y SELECT * FROM test_table;

powershell
docker inspect lamp-apache --format "{{json .NetworkSettings.Networks}}"
docker inspect lamp-mariadb --format "{{json .Mounts}}"

09

Solución de problemas frecuentes

ProblemaCausa probableSolución
Error 500 o "Internal Server Error"Apache no puede contactar con PHP-FPMRevisar que el nombre php-fpm coincide en vhost.conf y docker-compose.yml
La página muestra el código PHP como texto planoApache no está delegando correctamente a PHP-FPMVerificar que vhost.conf está bien montado y que se ejecuta el comando Include
"could not find driver" al conectar con la base de datosFaltan las extensiones PDOVerificar que docker-php-ext-install pdo pdo_mysql mysqli está en el Dockerfile
Error de conexión a MariaDBEl host en PHP es localhost en lugar de mariadbEn Docker, usar el nombre del servicio como host: mariadb
El puerto 8080 ya está en usoOtro servicio ocupa el puertoCambiar el mapeo en docker-compose.yml a "8081:80"
Modifico init.sql y no se aplicaSolo se ejecuta la primera vez que se crea el volumendocker compose down -v y volver a levantar
Contenedor no arrancaError de configuracióndocker compose logs <servicio>
Consejo

Ante cualquier error, empieza siempre por docker compose logs <servicio> y docker compose ps.

10

Conceptos aprendidos y siguientes pasos

Conceptos aprendidos

ConceptoDónde lo has usado
Contenedores separados por responsabilidadApache sirve, PHP ejecuta, MariaDB almacena
Red interna de DockerLos contenedores se comunican por nombre de servicio (php-fpm, mariadb)
VolúmenesEl código local se sincroniza con el contenedor; los datos de MariaDB persisten
Variables de entornoConfiguración de MariaDB sin tocar archivos
Orquestación con ComposeUn solo comando levanta todo el stack
FastCGIProtocolo de comunicación entre Apache y PHP-FPM
Dockerfile personalizadoAñadir extensiones PHP a la imagen oficial

Siguientes pasos

Una vez domines este stack, puedes:

  • Añadir phpMyAdmin para gestionar MariaDB desde el navegador.
  • Instalar Composer dentro del contenedor PHP-FPM para gestionar dependencias.
  • Migrar a Nginx si necesitas mejor rendimiento con archivos estáticos.
  • Añadir Redis para caché y sesiones.
  • Usar este entorno como base para Laravel o Symfony.

La estructura de tres contenedores que has montado es la base de prácticamente cualquier aplicación PHP moderna en producción.

  1. docker compose up -d --build
  2. Abre http://localhost:8080 y verifica que ves la tabla con datos.

  4. docker compose up -d

  7. docker compose up -d --build
  8. Comprueba que los datos han desaparecido (la base de datos se recrea).

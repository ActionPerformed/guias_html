Cómo se ejecuta el código de esta guía

Un playground no es un servidor. Saber qué falta es parte del aprendizaje.

Lee esto antes de ejecutar nada

La consola integrada cubre variables, tipos, operadores, control de flujo, funciones, arrays y excepciones. Lo que depende de una petición HTTP real —cabeceras, cookies del navegador, sesiones que sobreviven entre páginas, subida de archivos, base de datos— no se puede reproducir: no hay servidor al otro lado.

Todo lo marcado con Solo entorno real está para que entiendas el concepto y lo reconozcas en clase, aunque aquí no se ejecute.

Comprueba qué funciona y qué no

Pulsa cualquier elemento para ver el veredicto y, cuando exista, la forma de simularlo.

Regla de oro

Si un ejemplo no arranca en la consola, no te bloquees: comprueba primero si pertenece a la categoría "entorno real". La lógica del lenguaje se aprende igual; lo que cambia es de dónde llegan los datos.

01

Lenguajes de guiones de servidor

Dónde se ejecuta el código decide casi todo lo demás.

¿Qué es un lenguaje de servidor?

Un lenguaje de guiones de servidor (server-side scripting) se ejecuta en el servidor web, no en el navegador del usuario. El servidor recibe una petición, ejecuta el código y devuelve al cliente el resultado, que normalmente es HTML.

03

Sintaxis básica

Lo mínimo para escribir cualquier script: delimitadores, variables, constantes y operadores.

Estructura de un script

Todo el código PHP vive entre <?php y ?>. Si el archivo es solo PHP, la etiqueta de cierre final se puede omitir, y de hecho se recomienda hacerlo para evitar espacios en blanco accidentales en la salida.

Variables y tipos

PHP tiene tipado dinámico: la variable no declara su tipo, lo toma del valor. Cambia los valores del ejemplo y observa cómo cambia var_dump().

Constantes

Una constante no cambia durante la ejecución y no lleva $. Se usan para configuración: nombre de la aplicación, rutas, versiones.

Operadores útiles desde PHP 7

Dos merecen atención especial: el operador de fusión de null ??, que evita avisos de índice indefinido, y la comparación estricta ===, que compara valor y tipo.

El clásico que suspende exámenes

5 == "5" es true porque PHP convierte tipos antes de comparar. 5 === "5" es false. En validaciones y comprobaciones de seguridad, usa siempre ===.

Interpolación de variables en cadenas

Las comillas dobles interpretan las variables; las simples no. Las llaves delimitan el nombre cuando hay riesgo de ambigüedad o cuando accedes a un elemento de array.

04

Estructuras de control

Decidir y repetir: condicionales, bucles y las dos sentencias que los modifican.

Condicionales

Tres herramientas para lo mismo, con matices: if/elseif/else para rangos, switch para valores concretos y match (PHP 8) cuando quieres una expresión que devuelve valor y compara de forma estricta.

Cambia $nota en el ejemplo y vuelve a ejecutar: verás cómo las tres estructuras responden a la vez.

Bucles

for cuando conoces el número de vueltas, while cuando dependes de una condición, do-while cuando el cuerpo debe ejecutarse al menos una vez y foreach siempre que trabajes con arrays, que en la práctica será casi siempre.

break y continue

continue salta a la siguiente vuelta; break abandona el bucle. Predice la salida antes de ejecutar.

05

Funciones

Encapsular lógica, declarar tipos y trabajar con funciones como valores.

Declaración básica

Parámetros por defecto y tipos

Declarar tipos de parámetros y de retorno documenta la función y permite que PHP detecte errores antes. Con declare(strict_types=1) al principio del archivo, las conversiones silenciosas dejan de aceptarse.

Funciones anónimas y de flecha

Una función anónima se guarda en una variable y se pasa como argumento. La función de flecha (PHP 7.4) es su versión corta para una sola expresión, y captura automáticamente las variables del entorno.

Funciones internas que usarás a diario

PHP trae una biblioteca estándar enorme. Este puñado cubre el 80 % del trabajo con cadenas, arrays y números.

Formulario con POST

Comprobar $_SERVER['REQUEST_METHOD'] evita procesar el formulario cuando la página se carga por primera vez.

Validación y sanitización

Son dos operaciones distintas y las dos son necesarias: validar es comprobar que el dato es aceptable; sanitizar es neutralizar el dato al mostrarlo. La regla práctica: valida al entrar, escapa al salir.

Sin htmlspecialchars hay XSS

Si imprimes texto del usuario tal cual y ese texto contiene <script>, el navegador lo ejecutará. Ejecuta el ejemplo y fíjate en la diferencia entre la pestaña Salida y la pestaña HTML generado.

07

Cookies y sesiones

HTTP no recuerda nada. La persistencia hay que construirla.

HTTP es un protocolo sin estado: cada petición es independiente y el servidor no sabe si quien pide esta página es el mismo que pidió la anterior. Para reconocer al usuario entre páginas se usan cookies, que viven en el cliente, o sesiones, que viven en el servidor.

Cookies: datos en el cliente

Solo entorno real
setcookie() envía una cabecera HTTP, y las cabeceras deben salir antes que cualquier contenido. En la consola no hay respuesta HTTP que modificar, así que se simula escribiendo directamente en el array $_COOKIE.

Sesiones: datos en el servidor

El servidor guarda los datos y entrega al navegador solo un identificador de sesión. Por eso una sesión puede guardar un carrito entero mientras que una cookie apenas admite 4 KB.

Solo entorno real
Aquí $_SESSION funciona durante una ejecución, pero se vacía en cuanto vuelves a pulsar Ejecutar: no hay servidor que conserve el archivo de sesión entre peticiones.

Usuarios y entornos diferenciados

Quién eres determina qué ves. Esa frase es todo el control de acceso.

AdministradorTodo, incluida la zona de administración

Flujo de autenticación

  1. Registro: guardar el usuario con la contraseña pasada por password_hash().
  2. Login: verificar con password_verify() y guardar el resultado en la sesión.
  3. Cada página protegida: comprobar la sesión; si no hay, redirigir al login.
  4. Logout: destruir la sesión.

Hash de contraseñas

Este ejemplo sí se ejecuta. Genera el hash, verifícalo y prueba a cambiar la contraseña introducida.

Dos reglas sin excepción

Nunca guardes contraseñas en texto plano. Nunca uses MD5 ni SHA1 para contraseñas: están diseñados para ser rápidos, que es justo lo contrario de lo que necesita una contraseña.

09

Buenas prácticas y seguridad básica

Siete costumbres que separan un script de prácticas de un script entregable.

Lista de comprobación

Marca los puntos conforme los incorpores a tus ejercicios.

  • declare(strict_types=1); al principio de los scripts con lógica seria.
  • htmlspecialchars() en toda salida que provenga del usuario.
  • filter_var() para validar correos, URLs y números.
  • password_hash() y password_verify() para contraseñas.
  • session_start() al inicio de cada archivo que use sesiones.
  • No confiar nunca en $_GET ni $_POST sin validar.
  • No mostrar errores en producción: display_errors = Off.

Depurar sin volverse loco

var_dump() muestra tipo y valor, que es justo lo que necesitas cuando algo "parece" correcto pero no lo es. print_r() es más legible para arrays.

Errores frecuentes en clase

Punto y coma olvidado, comillas sin cerrar, $ ausente delante de una variable, comparar con = en lugar de ==, y llamar a una función antes de declararla dentro de un condicional. Cuando el error sea "unexpected", mira la línea anterior a la que indica el mensaje.

Qué entiende la consola integrada

El intérprete cubre un subconjunto de PHP 8 suficiente para toda la guía. Conviene saber dónde están sus límites.

Sí lo soporta

Variables y tipos, cadenas con interpolación, arrays indexados y asociativos, todos los operadores del bloque 2, if/elseif/else, switch, match, for, while, do-while, foreach, break y continue, funciones con tipos y valores por defecto, funciones anónimas y de flecha, try/catch/finally, throw y la jerarquía de excepciones estándar.

No lo soporta

Clases y objetos propios, espacios de nombres, include y require, acceso a archivos, conexiones a bases de datos, cabeceras HTTP reales y cualquier extensión del sistema. En esos casos el mensaje de error lo dice explícitamente.

Cuando algo no encaje, el botón Abrir en 3v4l de cada bloque envía ese mismo código a un intérprete de PHP real, con conexión a internet.

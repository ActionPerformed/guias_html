🎯 ¿Qué vas a construir?

Una MiniApp de Biblioteca que reutiliza tu login de la actividad anterior y añade:

  • Un catálogo de materiales (libros, revistas, DVDs) modelados como objetos PHP.
  • Herencia: clase base MaterialBiblioteca y subclases por tipo.
  • Interfaces: Prestable para el contrato de préstamo.
  • Traits: código reutilizable para fechas y logging.
  • Persistencia: los objetos viven en MariaDB pero circulan por tu código como objetos.
  • Préstamos: un usuario puede tomar prestado material disponible.

Escenario: eres el desarrollador de la biblioteca de tu centro. Los usuarios consultan el catálogo y piden préstamos; los administradores gestionan el fondo bibliográfico.

Duración total: 6 horas (3 sesiones de 2 h).

🧱 Cómo se organiza el código en PHP: require_once

En Java usabas import. En PHP no hay import: hay que incluir físicamente el archivo donde está la clase. La forma más segura es:

require_once __DIR__ . '/ruta/al/archivo.php';
  • require_once = "si no se ha incluido ya, inclúyelo; si ya está, no hagas nada".
  • __DIR__ = el directorio del archivo actual (evita líos con rutas relativas).
  • El orden importa: no puedes usar una clase antes de haber incluido su archivo.

⚠️ Error típico: Class 'Libro' not found. Casi siempre significa que olvidaste el require_once de Libro.php, o que la ruta está mal. No es como Java, donde el import no depende de dónde esté el archivo en el sistema.

💡 Nota para curiosos: en proyectos grandes se usa un autoloader (Composer, spl_autoload_register) que carga las clases automáticamente. Lo veremos como ampliación al final. Por ahora, require_once explícito.

🧠 POO en PHP vs Java: las diferencias que te van a morder

Concepto Java PHP
Declarar clase public class Libro { } class Libro { }
Atributo private String titulo; private string $titulo;
Acceso libro.getTitulo() $libro->getTitulo()
Constructor public Libro(String t) { ... } public function __construct(string $t) { ... }
this this.titulo $this->titulo
Lista ArrayList<Libro> array (sin genéricos)
Importar import ...; require_once __DIR__ . '/...';
Null null null (pero ?string $x para nullable)
Método estático Clase.metodo() Clase::metodo()
Constante Clase.CONSTANTE Clase::CONSTANTE

🔑 Regla mnemotécnica: en PHP, todo acceso a atributo o método lleva ->, todo nombre de variable empieza por $, y todo acceso estático lleva ::.

🧪 Ejercicio de calentamiento: traduce de Java a PHP (10 min)

Traduce mentalmente (o en un papel) estas líneas de Java a PHP. No las ejecutes todavía:

public class Persona {
    private String nombre;
    private int edad;

    public Persona(String nombre, int edad) {
        this.nombre = nombre;
        this.edad = edad;
    }

    public String getNombre() { return nombre; }
    public int getEdad() { return edad; }
}
<?php
class Persona {
    private string $nombre;
    private int $edad;

    public function __construct(string $nombre, int $edad) {
        $this->nombre = $nombre;
        $this->edad = $edad;
    }

    public function getNombre(): string { return $this->nombre; }
    public function getEdad(): int { return $this->edad; }
}

Diferencias clave: $ en variables y atributos, -> en vez de ., function en métodos, tipos de retorno con : string después de los paréntesis.

📄 Paso 1: clase base MaterialBiblioteca

Crea src/classes/MaterialBiblioteca.php:

<?php
// src/classes/MaterialBiblioteca.php

class MaterialBiblioteca {
    private int $id;
    private string $titulo;
    private string $autor;
    private ?int $anio;
    private bool $disponible;

    public function __construct(
        string $titulo,
        string $autor,
        ?int $anio = null,
        bool $disponible = true,
        int $id = 0
    ) {
        $this->titulo     = $titulo;
        $this->autor      = $autor;
        $this->anio       = $anio;
        $this->disponible = $disponible;
        $this->id         = $id;
    }

    public function getId(): int          { return $this->id; }
    public function getTitulo(): string   { return $this->titulo; }
    public function getAutor(): string    { return $this->autor; }
    public function getAnio(): ?int       { return $this->anio; }
    public function isDisponible(): bool  { return $this->disponible; }

    public function setTitulo(string $t): void { $this->titulo = $t; }
    public function setDisponible(bool $d): void { $this->disponible = $d; }

    public function mostrarFicha(): string {
        $anio = $this->anio ?? 's/f';
        return sprintf('[%s] %s — %s (%s)',
            $this->tipoMaterial(), $this->titulo, $this->autor, $anio
        );
    }

    public function tipoMaterial(): string {
        return 'material';
    }

    public function antiguedad(): int {
        if ($this->anio === null) return 0;
        return (int)date('Y') - $this->anio;
    }
}

📌 Fíjate en:

  • private en todos los atributos → encapsulación.
  • Parámetros por defecto (?int $anio = null, int $id = 0). Los usaremos para hidratar desde BBDD.
  • ?int = "int o null" (nullable).
  • sprintf con %s es como String.format en Java.
  • tipoMaterial() devuelve genérico; las subclases lo cambiarán (polimorfismo, Bloque 2).

📄 Paso 2: subclase Libro

Crea src/classes/Libro.php:

<?php
// src/classes/Libro.php
require_once __DIR__ . '/MaterialBiblioteca.php';

class Libro extends MaterialBiblioteca {
    private string $isbn;

    public function __construct(
        string $titulo,
        string $autor,
        ?int $anio,
        string $isbn,
        bool $disponible = true,
        int $id = 0
    ) {
        parent::__construct($titulo, $autor, $anio, $disponible, $id);
        $this->isbn = $isbn;
    }

    public function getIsbn(): string { return $this->isbn; }

    public function tipoMaterial(): string { return 'Libro'; }

    public function mostrarFicha(): string {
        return parent::mostrarFicha() . ' · ISBN: ' . $this->isbn;
    }
}

📌 Fíjate en: extends = herencia. parent::__construct(...) = super(...) de Java. parent::mostrarFicha() reutiliza la del padre. tipoMaterial() sobrescribe.

Son void porque los setters no devuelven nada: solo modifican el estado interno. Misma convención que en Java.

Añade un atributo private string $editorial = '' a Libro con getter y setter. ¿Qué diferencia hay entre darle valor por defecto y exigirlo en el constructor?

🧬 Bloque 2 — Encapsulación, herencia y polimorfismo

⏱ 80 min

🎯 Criterio trabajado: CE b) — encapsulación, herencia y polimorfismo.

🧠 Los tres pilares, en una frase cada uno

  • Encapsulación: el objeto oculta su estado y solo lo expone por métodos.
  • Herencia: una clase hereda atributos y métodos de otra.
  • Polimorfismo: el mismo método se comporta distinto según el objeto real.

🔑 "Encapsulo para que no me toquen las tripas, heredo para no repetirme, y el polimorfismo me deja hablar igual a objetos distintos."

🧠 ¿Qué es protected?

Visibilidad Accesible desde Java
public Todos public
protected La clase y sus subclases protected
private Solo la clase private

Si quieres que una subclase pueda leer un atributo del padre sin pasar por getter, decláralo protected. Como usamos parent::mostrarFicha(), no lo necesitamos — pero es útil saberlo.

🧪 Retos

Añade a MaterialBiblioteca un método resumen(): string que devuelva solo tipo + título. Sobrescríbelo en Libro para que devuelva Libro + título + autor. ¿Qué principio de POO aplicas?

En MaterialBiblioteca:

public function resumen(): string {
    return $this->tipoMaterial() . ': ' . $this->titulo;
}

En Libro:

public function resumen(): string {
    return 'Libro: ' . $this->titulo . ' — ' . $this->autor;
}

Polimorfismo por sobrescritura (override).

Nota sobre resumen(): resumen() no se usa en el código principal de la guía. Es un reto para practicar la sobrescritura (override). Si quieres verlo funcionando, añádelo tú mismo al foreach de index.php:

<li><?= htmlspecialchars($m->resumen()) ?></li>

Pero no lo busques en el código base: no está, y no pasa nada. Es un ejercicio de diseño, no una pieza del flujo principal.

¿Qué pasa si en Libro olvidas llamar a parent::__construct(...)? Prueba a comentarlo.

PHP no obliga a llamar al constructor del padre (a diferencia de Java, donde super() es implícito si no hay parámetros). Si lo omites, los atributos titulo, autor, etc. quedan sin inicializar (en PHP 8 toman el valor por defecto del tipo: "" para string, 0 para int). El objeto existe pero está vacío.

Regla: si el padre tiene constructor con parámetros, llámalo siempre.

Escribe public function prestar(): bool en MaterialBiblioteca que ponga disponible = false y devuelva true si estaba disponible, o false si ya estaba prestado. ¿Por qué es mejor esto que un setDisponible(false) a pelo? 

public function prestar(): bool {
    if (!$this->disponible) return false;
    $this->disponible = false;
    return true;
}

public function devolver(): void {
    $this->disponible = true;
}

Protege la invariante: no se puede prestar algo ya prestado. Con setters sueltos, cualquiera puede dejar el objeto inconsistente. Esto es encapsulación de verdad: los métodos representan operaciones del dominio, no simples setX.

    echo $m->mostrar_ficha();

El método se llama mostrarFicha (camelCase), no mostrar_ficha (snake_case). PHP distingue mayúsculas y minúsculas en nombres de métodos y atributos (a diferencia de las funciones nativas). Además, el error sería Call to undefined method Libro::mostrar_ficha().

Convención: camelCase para métodos, PascalCase para clases, snake_case para variables y nombres de BBDD.

Crea un array con 6 materiales (2 de cada tipo) y recórrelo mostrando tipoMaterial() + mostrarFicha(). ¿Cuántas veces se ejecuta cada mostrarFicha()?

    new Revista('Muy Interesante', 'Zinet', 2024, 512),
    new DVD('El Padrino', 'Coppola', 1972, 175),
    new DVD('Blade Runner', 'Scott', 1982, 117),

🔌 Bloque 3 — Interfaces y traits

⏱ 65 min

🎯 Criterio trabajado: CE c) — interfaces y mecanismos de reutilización.

🧠 Interfaz vs trait: no son lo mismo

  • Interfaz: un contrato. Define qué métodos debe tener una clase. Una clase puede implementar varias.
  • Trait: un bloque de código reutilizable que se "inyecta" en una clase. No existe en Java (equivalente: mixins).
Interfaz Trait
¿Define contrato? Sí No
¿Aporta implementación? No Sí
¿Cuántos por clase? Muchos Muchos
¿Existe en Java? Sí No (equivalente: mixins)
Uso típico Prestable, Comparable TieneFechas, Loggable

🔑 Interfaz = qué debe existir. Trait = cómo se hace, para reutilizar.

📄 Paso 1: interfaz Prestable

Crea src/classes/Prestable.php:

<?php
interface Prestable {
    public function prestar(): bool;
    public function devolver(): void;
    public function diasPrestamo(): int;
}

📌 Una interfaz solo declara firmas. Igual que en Java.

📄 Paso 2: implementar la interfaz

Modifica MaterialBiblioteca para que implemente Prestable:

<?php
require_once __DIR__ . '/Prestable.php';

class MaterialBiblioteca implements Prestable {
    // ... atributos y constructor iguales ...

    public function prestar(): bool {
        if (!$this->disponible) return false;
        $this->disponible = false;
        return true;
    }

    public function devolver(): void { $this->disponible = true; }
    public function isDisponible(): bool { return $this->disponible; }

    public function diasPrestamo(): int { return 15; }
}

Y sobrescríbelo en DVD:

public function diasPrestamo(): int { return 3; }

📄 Paso 3: trait Loggable

💡 ¿Por qué un trait aquí? Porque log() no tiene nada que ver con ser un material de biblioteca. Es una capacidad transversal: la queremos reutilizar en varias clases sin forzar herencia. Ese es exactamente el caso de uso de un trait.

Crea src/classes/traits/Loggable.php:

<?php
trait Loggable {
    public function log(string $mensaje): void {
        error_log(sprintf('[%s] %s: %s',
            date('Y-m-d H:i:s'),
            static::class,
            $mensaje
        ));
    }
}

📌 Dentro de un trait puedes usar $this->... y static::class. El trait se comporta como si su código estuviera escrito en la clase que lo usa.

📄 Paso 4: trait TieneFechas (con hidratación desde BBDD)

Crea src/classes/traits/TieneFechas.php:

<?php
trait TieneFechas {
    private ?string $fechaCreacion = null;

    public function setFechaCreacion(?string $fecha): void {
        $this->fechaCreacion = $fecha;
    }

    public function getFechaCreacion(): ?string {
        return $this->fechaCreacion;
    }

    public function fechaFormateada(): string {
        if ($this->fechaCreacion === null) return '—';
        return date('d/m/Y', strtotime($this->fechaCreacion));
    }
}

⚠️ Ojo: este trait se va a usar de verdad en el Bloque 4, cuando hidratemos el campo creado_en de la BBDD. No es decorativo.

📄 Paso 5: usar los traits

Añade los traits a MaterialBiblioteca:

<?php
require_once __DIR__ . '/Prestable.php';
require_once __DIR__ . '/traits/TieneFechas.php';
require_once __DIR__ . '/traits/Loggable.php';

class MaterialBiblioteca implements Prestable {
    use TieneFechas, Loggable;

    // ... resto igual ...
}

Ahora cualquier material tiene setFechaCreacion(), getFechaCreacion(), fechaFormateada() y log().

🔁 Comparación Java: en Java habrías usado una clase abstracta o composición. Los traits son la respuesta de PHP a "quiero compartir código sin forzar jerarquía".

🧪 Retos

¿Qué error da PHP si una clase dice implements Prestable pero no define diasPrestamo()? Pruébalo.

Fatal error: Class Libro contains 1 abstract method and must therefore be declared abstract or implement the remaining method (Prestable::diasPrestamo)

PHP obliga a implementar todos los métodos de la interfaz. Misma garantía que Java.

Añade a Prestable un método puedePrestarse(): bool que devuelva true si el material está disponible y su año es anterior a 2010. Implementa la lógica en MaterialBiblioteca.

En Prestable.php:

public function puedePrestarse(): bool;

En MaterialBiblioteca:

public function puedePrestarse(): bool {
    return $this->disponible
        && $this->anio !== null
        && $this->anio < 2010;
}

Reflexiona: ¿tiene sentido para DVDs? Probablemente no. Aquí se ve la utilidad del polimorfismo: podrías sobrescribirla en DVD para que siempre devuelva true si está disponible.

Nota sobre puedePrestarse(): puedePrestarse() tampoco se usa en el código principal. Es un reto para pensar dónde vive la lógica de negocio: en el objeto, no en el controlador.

Si quisieras usarlo de verdad, el sitio natural sería prestar.php, sustituyendo:

if ($material->prestar()) { ... }

por algo como:

if (!$material->puedePrestarse()) {
    $error = 'Este material no se puede prestar.';
} elseif ($material->prestar()) {
    $repo->setDisponible($id, false);
    $repo->registrarPrestamo($id, currentUser()['id']);
}

Fíjate en lo que aparece: una rama de error. Eso ya es gestión de casos, no solo lógica de dominio. Por eso el código principal se queda con la versión simple: para no meter complejidad que aún no toca. El reto es tuyo, pero no es obligatorio integrarlo.

Encuentra el error.

Este trait pretende añadir un código identificador, pero al usarlo da error:

trait Identificable {
    private $codigo = '';
    public function getCodigo() { return $this->codigo; }
}

class Libro extends MaterialBiblioteca {
    use Identificable;
}

En realidad este código funciona en PHP (los tipos son opcionales). El error típico es otro: si MaterialBiblioteca también usa Identificable, PHP puede quejarse de conflicto si los métodos difieren. La solución es insteadof o as: 

use Identificable, OtraCosa {
    Identificable::getCodigo insteadof OtraCosa;
    OtraCosa::getCodigo as getCodigoAlternativo;
}

Reflexiona: los traits son potentes pero pueden liar. Regla: un trait = una responsabilidad concreta. Si empiezas a necesitar insteadof, replantea el diseño.

¿Por qué no podemos poner diasPrestamo() en un trait en lugar de en la interfaz?

Sí se puede, pero cambia el significado. En un trait, no obliga a las clases a implementarlo: solo lo aporta a quien lo use. En la interfaz, obliga a todas las clases que implementan Prestable. Regla: interfaz = qué debe existir; trait = cómo se hace.

Usa log() dentro de prestar() para registrar cada préstamo. Comprueba que aparece en docker compose logs -f php-fpm.

public function prestar(): bool {
    if (!$this->disponible) {
        $this->log("Intento fallido de préstamo: {$this->titulo}");
        return false;
    }
    $this->disponible = false;
    $this->log("Préstamo realizado: {$this->titulo}");
    return true;
}

Ejecuta docker compose logs -f php-fpm en una terminal y haz un préstamo desde el navegador.

B4

🗄️ Bloque 4 — Persistencia: de la BBDD a los objetos

⏱ 75 min

🎯 Criterio trabajado: integración de POO con la capa de persistencia.

🧠 El problema: los objetos viven en memoria, los datos en disco

Hasta ahora has creado objetos "a mano" (new Libro(...)). En una app real los datos vienen de la BBDD. Necesitamos un puente:

  • Hidratar = convertir una fila de BBDD en un objeto PHP.
  • Persistir = guardar un objeto en BBDD (INSERT/UPDATE).
  • Repositorio = clase que se encarga de todo eso. El resto de la app no escribe SQL: pide al repositorio.

🔑 Regla: las clases de dominio (Libro, DVD...) no saben SQL. El repositorio sí. Separación de responsabilidades.

Que significa hidratar?

El termino viene del mundo de los ORM (Hibernate en Java, Doctrine en PHP) y se usa para describir una operacion muy concreta:

  • Hidratar = rellenar un objeto vacio con los datos que vienen de la BBDD.

La metafora: un objeto recien creado esta seco (sin datos). Al pasarle una fila de BBDD, se hidrata (se llena de contenido). Una vez hidratado, el objeto ya tiene su titulo, autor, ano, etc., y se comporta como cualquier otro objeto de tu dominio.

📊 Diagrama de la capa de persistencia

📄 Paso 1: MaterialRepo

Crea src/repos/MaterialRepo.php:

<?php
require_once __DIR__ . '/../config/db.php';
require_once __DIR__ . '/../classes/Libro.php';
require_once __DIR__ . '/../classes/Revista.php';
require_once __DIR__ . '/../classes/DVD.php';

class MaterialRepo {

    public function findAll(): array {
        $stmt = db()->query('SELECT * FROM materiales ORDER BY tipo, titulo');
        $materiales = [];
        foreach ($stmt->fetchAll() as $fila) {
            $materiales[] = $this->hidratar($fila);
        }
        return $materiales;
    }

    public function findById(int $id): ?MaterialBiblioteca {
        $stmt = db()->prepare('SELECT * FROM materiales WHERE id = ?');
        $stmt->execute([$id]);
        $fila = $stmt->fetch();
        return $fila ? $this->hidratar($fila) : null;
    }

    /**
     * Convierte una fila de BBDD en el objeto PHP correcto.
     * También hidrata la fecha de creación desde 'creado_en'.
     */
    private function hidratar(array $fila): MaterialBiblioteca {
        $material = match ($fila['tipo']) {
            'libro'   => new Libro(
                $fila['titulo'], $fila['autor'], (int)$fila['anio'],
                $fila['isbn'] ?? '', (bool)$fila['disponible'], (int)$fila['id']
            ),
            'revista' => new Revista(
                $fila['titulo'], $fila['autor'], (int)$fila['anio'],
                (int)$fila['numero'], (bool)$fila['disponible'], (int)$fila['id']
            ),
            'dvd'     => new DVD(
                $fila['titulo'], $fila['autor'], (int)$fila['anio'],
                (int)$fila['duracion_min'], (bool)$fila['disponible'], (int)$fila['id']
            ),
            default   => throw new RuntimeException("Tipo desconocido: {$fila['tipo']}"),
        };
        $material->setFechaCreacion($fila['creado_en'] ?? null);
        return $material;
    }

    public function setDisponible(int $id, bool $disponible): void {
        $stmt = db()->prepare('UPDATE materiales SET disponible = ? WHERE id = ?');
        $stmt->execute([$disponible ? 1 : 0, $id]);
    }

    public function registrarPrestamo(int $materialId, int $usuarioId): void {
        $stmt = db()->prepare(
            'INSERT INTO prestamos (material_id, usuario_id) VALUES (?, ?)'
        );
        $stmt->execute([$materialId, $usuarioId]);
    }
}

📌 Fíjate en:

  • match es como switch pero devuelve valor (PHP 8+).
  • (int) y (bool) castean: PDO devuelve strings.
  • throw new RuntimeException(...) si el tipo es desconocido.
  • El repositorio depende de las clases; las clases no dependen del repositorio.
  • setFechaCreacion() viene del trait TieneFechas. Aquí se usa de verdad.

Añade un método crear(MaterialBiblioteca $m): int que inserte un material y devuelva su id. Divide y vencerás: primero detecta el tipo, luego extrae los campos específicos, luego haz el INSERT.

public function crear(MaterialBiblioteca $m): int {
    $tipo = match (true) {
        $m instanceof Libro   => 'libro',
        $m instanceof Revista => 'revista',
        $m instanceof DVD     => 'dvd',
        default               => throw new InvalidArgumentException('Tipo no soportado'),
    };

    $isbn   = $m instanceof Libro   ? $m->getIsbn()        : null;
    $numero = $m instanceof Revista ? $m->getNumero()      : null;
    $dur    = $m instanceof DVD     ? $m->getDuracionMin() : null;

    $stmt = db()->prepare(
        'INSERT INTO materiales (tipo, titulo, autor, anio, isbn, numero, duracion_min, disponible)
         VALUES (?, ?, ?, ?, ?, ?, ?, ?)'
    );
    $stmt->execute([
        $tipo, $m->getTitulo(), $m->getAutor(), $m->getAnio(),
        $isbn, $numero, $dur, $m->isDisponible() ? 1 : 0
    ]);
    return (int)db()->lastInsertId();
}

Reflexiona: aquí usamos instanceof porque necesitamos métodos específicos de la subclase. Es un downcast legítimo. Se podría evitar con un toArray() polimórfico en cada clase. Más limpio, pero más código.

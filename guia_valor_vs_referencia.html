1 · La idea central

🪣 Por valor

Se pasa una copia. Lo que hagas dentro no afecta al original.

🚰 Por referencia

Se pasa un alias de la variable. Lo que hagas dentro sí afecta al original.
💡 «Valor» y «referencia» significan cosas distintas en Java y en PHP. No asumas que son lo mismo.
2 · Java: todo se pasa por valor

En Java no existe el paso por referencia. Siempre se pasa una copia, pero hay dos casos.

Se copia el valor directamente (int, boolean, double…).

void cambiar(int x) {
    x = 99;   // solo cambia la copia
}
int a = 1;
cambiar(a);
System.out.println(a);   // imprime 1

Se copia la referencia al objeto (su «dirección»).

void modificar(int[] arr) {
    arr[0] = 99;         // ✅ SÍ afecta: modifica el objeto apuntado
    arr = new int[]{7};  // ❌ NO afecta: reasigna la copia local
}
int[] datos = {1, 2, 3};
modificar(datos);
System.out.println(datos[0]);   // imprime 99
✅ Modificar el contenido → afecta al original.
❌ Reasignar la variable → no afecta.

La copia de la referencia apunta al mismo objeto, pero es otra variable. Si cambias a qué apunta la copia, el original sigue apuntando a lo de antes.

⚠️ String es inmutable: cualquier «modificación» crea un objeto nuevo, así que nunca verás cambios fuera. No es un caso especial del paso por valor, es inmutabilidad.
3 · PHP: por valor, o por referencia con &

Por defecto todo se pasa por valor, pero PHP te deja elegir la referencia con & en la definición de la función.

function modificar($arr) {
    $arr[0] = 99;      // ❌ NO afecta (se copió el array)
    $arr = [7];        // ❌ tampoco
}
$datos = [1, 2, 3];
modificar($datos);
echo $datos[0];   // imprime 1
💡 En PHP los arrays no son objetos, son tipos de valor: se copian. Es la raíz de la mayoría de confusiones al venir de Java.
💡 Internamente usa copy-on-write: solo se duplica de verdad al modificar, así que el rendimiento no es un problema.
function modificar(&$arr) {
    $arr[0] = 99;   // ✅ afecta al original
    $arr = [7];     // ✅ también afecta (¡reasigna el original!)
}
$datos = [1, 2, 3];
modificar($datos);
echo $datos[0];   // imprime 7

Con & la variable de dentro es un alias: la misma variable con dos nombres.

⚠️ Error común: poner & en la llamada.
modificar(&$datos); ❌ error de sintaxis · modificar($datos); ✅ el & va solo en la definición.
💡 Objetos en PHP (desde PHP 5): como en Java, se pasa la referencia al objeto, así que modificar sus propiedades afecta al original sin &. Solo arrays y escalares lo necesitan.

5 · El error clásico: la cadena de funciones

Si pasas un array por varias funciones encadenadas, cada eslabón debe estar bien.

❌ Eslabón roto
function interna(&$datos) {
    $datos[0] = 99;
}
function intermedia($datos) { // sin &
    interna($datos);
}
$arr = [1, 2, 3];
intermedia($arr);
echo $arr[0];   // 1 ❌
✅ Cadena completa
function interna(&$datos) {
    $datos[0] = 99;
}
function intermedia(&$datos) {
    interna($datos);
}
$arr = [1, 2, 3];
intermedia($arr);
echo $arr[0];   // 99 ✅

intermedia() hizo una copia antes de llamar a interna(): los cambios se quedan en esa copia y desaparecen al terminar. Solución: & en todos los eslabones. En Java esto no pasa con objetos: mientras no reasignes la referencia, los cambios se propagan solos.

6 · Analogía del estanque

🪣 Por valor

Te dan un cubo con agua copiada. Haz lo que quieras: el estanque no cambia.

🚰 Por referencia

Te dan una tubería conectada al estanque. Todo lo que hagas afecta al real.
🗺️ Java con objetos: te dan una tubería… hacia una copia del mapa que dice dónde está el estanque. Si sigues el mapa, llegas al estanque (modificas contenido). Si cambias el mapa por otro, el estanque antiguo sigue igual.
7 · Reglas rápidas y resumen

Java

  • Todo se pasa por valor.
  • Con objetos el «valor» es la referencia: modificar contenido sí, reasignar no.
  • No puedes forzar paso por referencia.
  • String es inmutable.

PHP

  • Por defecto, todo por valor (los arrays se copian).
  • Con & en la firma, alias real.
  • En cadenas, & en cada eslabón.
  • Los objetos se comportan como en Java.
«Referencia» significa cosas distintas: en Java es dirección a un objeto; en PHP (&) es alias de variable. Si vienes de Java a PHP, el fallo típico es olvidar el & y preguntarte por qué tu función no modifica el array.
8 · Ponte a prueba

Predice la salida antes de abrir la solución.

Pregunta 1 · Java
void f(String s) { s = s + "b"; }
String t = "a";
f(t);
System.out.println(t);
Ver soluciónImprime a. String es inmutable: s + "b" crea un objeto nuevo y solo se reasigna la copia local.
Pregunta 2 · PHP
function f($o) { $o->x = 5; }
$p = new stdClass; $p->x = 1;
f($p);
echo $p->x;
Ver soluciónImprime 5. Los objetos se pasan como referencia al objeto, igual que en Java, sin necesidad de &.
Pregunta 3 · PHP
function interna($d) { $d[0] = 99; }
function intermedia(&$d) { interna($d); }
$a = [1, 2, 3];
intermedia($a);
echo $a[0];
Ver soluciónImprime 1. El eslabón roto está al final: interna() recibe una copia. Todos los eslabones que deben propagar el cambio necesitan &, incluido el último.
